## 场景1: 首次使用（完整修复流程）

```bash

# 2. 执行一键修复

# 
# 步骤: 特殊SQL问题修复
# ...
```


### 错误: Row size too large

```bash
# 修改VARCHAR转换阈值
cd /mnt/f/work/zq-platform/backend-django/core/management/commands
# 编辑 sql_syntax_fixer.py
# 找到 _fix_large_varchar 方法
# 将阈值从 1000 改为 500

    def _fix_large_varchar(self, line):
        # 将大于500字符的VARCHAR转为TEXT
        line = re.sub(
            r'VARCHAR\(([5-9]\d\d|[1-9]\d{3,})\)',  # 匹配500-999和1000+
            r'TEXT',
            line,
            flags=re.IGNORECASE
        )
        return line

# 然后重新运行导入
python manage.py import_oracle_sql --batch-id 1f5b4b14 --retry-failed --auto-fix
```

## 场景7: 性能优化

### 只处理失败的文件
```bash

    --batch-id 1f5b4b14 \

```

### 跳过超大文件
```bash
# 如果某些文件太大导致处理缓慢
python manage.py import_oracle_sql \
    --batch-id 1f5b4b14 \
    --retry-failed \
    --skip-large-files \
    --max-size 50  # 跳过超过50MB的文件
```

## 常见问题排查

```bash

python --version

# 确保在正确的目录
```

