# 设计文档：HIS 接口访问控制

## 上下文

### 背景

系统提供了文档 API 查询接口，可以查询 `docs/his/openapi.json` 中定义的所有 HIS 接口信息。但是，并不是所有的接口都应该被查询和访问。为了控制哪些接口可以被访问，需要实现接口级别的访问控制。

### 约束

- 必须与现有的文档 API 查询功能兼容
- 配置必须易于管理和更新
- 访问控制检查不应显著影响查询性能
- 默认情况下，只有指定的 14 个接口可以访问

### 利益相关者

- 系统管理员：需要控制哪些接口可以被访问
- 前端开发者：需要知道哪些接口可用
- AI Agent：需要知道当前可用的接口列表

## 目标 / 非目标

### 目标

1. 通过配置文件控制接口访问权限
2. 接口列表查询、详情查询和搜索都遵循访问控制规则
3. 提供清晰的错误提示，告知接口不可访问
4. 支持通过环境变量配置访问控制列表

### 非目标

1. 不实现基于用户角色的动态权限控制（当前为全局配置）
2. 不实现接口调用权限控制（仅控制查询权限）
3. 不修改 OpenAPI JSON 文档结构

## 决策

### 决策 1：配置存储方式

**选择**：使用环境变量 `HIS_API_ACCESS_CONTROL` 存储 JSON 字符串格式的配置

**理由**：
- 环境变量易于在不同环境（开发、测试、生产）中配置
- JSON 格式易于解析和维护
- 不需要修改数据库或配置文件结构

**配置格式**：
```json
{
  "ENC_INP_0001": true,
  "CLI_INP_0001": true,
  "DIAG_INP_0001": true,
  ...
}
```

**实现方式**：
```python
import os
import json

HIS_API_ACCESS_CONTROL = os.environ.get('HIS_API_ACCESS_CONTROL', '{}')
try:
    access_control = json.loads(HIS_API_ACCESS_CONTROL)
except json.JSONDecodeError:
    access_control = {}
```

### 决策 2：默认配置策略

**选择**：在代码中硬编码默认允许访问的 14 个接口

**理由**：
- 确保系统在没有配置的情况下也能正常工作
- 默认配置明确，易于理解和维护
- 可以通过环境变量覆盖默认配置

**实现方式**：
```python
# 默认允许访问的接口列表
DEFAULT_ACCESSIBLE_ENDPOINTS = {
    "ENC_INP_0001": True,      # 住院就诊信息
    "CLI_INP_0001": True,      # 住院患者过敏信息
    "DIAG_INP_0001": True,     # 住院患者诊断信息
    "CLI_INP_0010": True,      # 手术麻醉安排信息
    "CLI_INP_0006": True,      # 住院草药医嘱明细信息
    "CLI_INP_0005": True,      # 患者抗菌药物用药目的信息
    "CLI_NIS_0002": True,      # 体征数据变化信息(支持多院区)
    "CLI_NIS_0001": True,      # 体征数据明细信息
    "CLI_NIS_0021": True,      # 获取压疮记录上报接口
    "MEDINSUR_EMR_0006": True, # 住院电子病历死亡记录（医保）
    "FIN_INP_0009": True,      # 住院账单明细接口
    "ENC_OUTP_0001": True,     # 门诊患者就诊信息
    "CLI_OUTP_0004": True,     # 患者门诊处方发药信息接口
    "PER_OUTP_0002": True,     # 门诊患者基本健康信息接口
}

# 合并默认配置和环境变量配置
access_control = {**DEFAULT_ACCESSIBLE_ENDPOINTS, **access_control}
```

### 决策 3：访问控制检查位置

**选择**：在服务层（`doc_api_service.py`）进行访问控制检查

**理由**：
- 保持业务逻辑集中，便于维护
- API 层保持简洁，只负责请求处理和响应
- 便于单元测试

**实现方式**：
- 在 `get_endpoints_list` 中过滤不可访问的接口
- 在 `get_endpoint_detail` 中检查访问权限
- 在 `search_endpoints` 中过滤不可访问的接口

### 决策 4：错误处理策略

**选择**：不允许访问的接口返回 403 Forbidden 错误

**理由**：
- HTTP 403 是标准的权限拒绝状态码
- 提供清晰的错误信息，说明接口不可访问

**实现方式**：
```python
if not is_endpoint_accessible(operation_id):
    raise HttpError(403, f"接口 {operation_id} 不允许访问")
```

## 风险 / 权衡

### 风险

1. **配置错误**：如果环境变量配置格式错误，可能导致所有接口都无法访问
   - **缓解措施**：提供默认配置，配置解析失败时使用默认配置

2. **性能影响**：每次查询都需要检查访问权限
   - **缓解措施**：使用字典查找，时间复杂度 O(1)，性能影响可忽略

3. **配置管理**：环境变量配置可能不够直观
   - **缓解措施**：提供配置文档和示例

### 权衡

- **灵活性 vs 简单性**：使用 JSON 配置提供了灵活性，但需要正确配置。默认配置确保系统可以正常工作。
- **全局配置 vs 用户级配置**：当前实现为全局配置，简单高效。未来如果需要用户级配置，可以在此基础上扩展。

## 迁移计划

1. **部署前**：在环境变量中配置 `HIS_API_ACCESS_CONTROL`（可选）
2. **部署后**：验证默认配置生效，只有 14 个接口可以访问
3. **回滚**：如果出现问题，可以移除访问控制逻辑或清空环境变量配置
