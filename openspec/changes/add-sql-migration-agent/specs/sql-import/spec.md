## 新增需求

### 需求：SQL 迁移智能体核心功能

系统必须提供一个基于 LangGraph 的智能体来自动化管理 Oracle 到 MySQL 的迁移流程。

#### 场景：启动新迁移任务

- **当** 用户执行 `python -m AIagent.src.sql_import.migration_cli start --source <oracle_dir> --output <mysql_dir>`
- **那么** 系统创建新的迁移任务，生成唯一批次 ID（8位）
- **并且** 初始化迁移状态，设置当前阶段为 `convert`
- **并且** 保存状态到 `migration_state.json` 文件

#### 场景：智能阶段推进

- **当** 智能体执行某个阶段
- **那么** 首先检查该阶段的前置条件是否满足
- **并且** 通过 Claude Code CLI 执行阶段对应的命令
- **并且** 验证阶段完成条件
- **并且** 自动推进到下一阶段或报告错误

#### 场景：八阶段流程定义

- **当** 执行迁移流程
- **那么** 必须按顺序执行以下阶段：
  1. `convert`：Oracle 脚本转 MySQL 脚本
  2. `fix`：MySQL 脚本修复
  3. `import`：MySQL 脚本导入数据库
  4. `fk_extract`：从 Oracle SQL 提取外键关系
  5. `fk_import`：导入外键元数据到 table_foreignkey_metadata 表
  6. `config`：Table Config 生成
  7. `infer`：中文含义 LLM 推理
  8. `apply`：将中文含义导入 Table Config

---

### 需求：阶段完成度检查

系统必须能够智能检查每个阶段的完成进度。

#### 场景：检查 Oracle 转换阶段

- **当** 检查 `convert` 阶段完成度
- **那么** 统计源目录的 Oracle SQL 文件数量
- **并且** 统计输出目录的 MySQL SQL 文件数量
- **并且** 返回转换完成率和未转换文件列表

#### 场景：检查 MySQL 导入阶段

- **当** 检查 `import` 阶段完成度
- **那么** 查询 `sql_import_log` 表获取导入状态
- **并且** 按批次 ID 过滤统计成功/失败/待处理的文件数量
- **并且** 返回详细的导入状态报告

#### 场景：检查外键提取阶段

- **当** 检查 `fk_extract` 阶段完成度
- **那么** 统计源目录的 Oracle SQL 文件数量
- **并且** 统计外键输出目录的 `*_foreignkeys.json` 文件数量
- **并且** 返回提取完成率和提取策略统计

#### 场景：检查外键导入阶段

- **当** 检查 `fk_import` 阶段完成度
- **那么** 查询 `table_foreignkey_metadata` 表获取外键数量
- **并且** 与外键 JSON 文件中的总外键数比较
- **并且** 返回导入完成状态

#### 场景：检查中文含义推理阶段

- **当** 检查 `infer` 阶段完成度
- **那么** 统计需要推理的 SQL 文件数量
- **并且** 统计已生成的 `*_meaning.json` 文件数量
- **并且** 检查 `error_log.json` 中的失败任务

#### 场景：进度状态查询

- **当** 用户执行 `python -m AIagent.src.sql_import.migration_cli status`
- **那么** 显示当前迁移的整体进度百分比
- **并且** 显示每个阶段的状态（pending/in_progress/completed/failed）
- **并且** 显示当前阶段的详细进度（已处理数/总数）

---

### 需求：断点续做与重试

系统必须支持从中断点恢复迁移任务和重试失败项。

#### 场景：恢复迁移

- **当** 用户执行 `python -m AIagent.src.sql_import.migration_cli resume`
- **那么** 加载保存的 `migration_state.json`
- **并且** 从中断的阶段继续执行
- **并且** 跳过已成功完成的文件

#### 场景：重试失败项

- **当** 用户执行 `python -m AIagent.src.sql_import.migration_cli retry-failed`
- **那么** 只处理状态为 `failed` 的文件
- **并且** 保留原有批次 ID
- **并且** 更新状态记录

#### 场景：状态持久化

- **当** 每个阶段执行完成或发生错误
- **那么** 自动保存当前状态到 `migration_state.json`
- **并且** 包含批次 ID、当前阶段、各阶段状态、失败文件列表

---

### 需求：CSV 上下文支持

系统必须支持使用外部 CSV/Excel 文件作为中文含义推理的上下文。

#### 场景：指定 CSV 上下文文件

- **当** 用户指定 `--csv-context <file>` 参数
- **那么** 读取文件中的表名和中文名映射
- **并且** 在调用 LLM 推理时将映射信息加入提示词
- **并且** 优先使用 CSV 中的 NAMELABEL 作为表的中文含义

#### 场景：CSV/Excel 文件格式

- **当** 解析上下文文件
- **那么** 必须支持以下列：
  - `TABLENAME`：表名（必填）
  - `FORMDES`：表单分类描述（可选）
  - `NAMELABEL`：表单中文名称（必填）
- **并且** 表名自动转为大写进行匹配

---

### 需求：LangGraph 工作流集成

系统必须使用 LangGraph 构建迁移工作流。

#### 场景：工作流节点定义

- **当** 构建迁移工作流
- **那么** 必须包含以下节点：
  - `orchestrator`：任务调度和状态管理
  - `convert_node`：执行 Oracle 转 MySQL 命令
  - `fix_node`：执行 MySQL 脚本修复命令
  - `import_node`：执行 MySQL 导入命令
  - `fk_extract_node`：执行外键信息提取命令
  - `fk_import_node`：执行外键元数据导入命令
  - `config_node`：执行 Table Config 生成命令
  - `infer_node`：执行中文含义推理命令
  - `apply_node`：执行含义导入命令

#### 场景：Claude Code CLI 集成

- **当** 节点需要执行实际命令
- **那么** 通过 ClaudeCodeClient 执行对应的 Python/Django 命令
- **并且** 捕获命令输出和退出码
- **并且** 根据执行结果更新状态

#### 场景：条件路由

- **当** 某个阶段执行完成
- **那么** 检查阶段完成条件（通过 StageChecker）
- **如果** 完成条件满足，路由到下一阶段
- **如果** 存在失败且失败数超过阈值，暂停并等待用户决策
- **如果** 所有阶段完成，路由到 END 并输出完成报告

### 需求：大文件和批次管理

系统必须优化大文件处理和批次管理，复用现有 sql-import 的批次机制。

#### 场景：大文件检测与提示

- **当** 处理 SQL 文件时
- **那么** 检测文件大小（>10MB 标记为大文件）
- **并且** 在进度报告中显示大文件列表和预估处理时间

#### 场景：批次 ID 管理

- **当** 启动新的迁移任务
- **那么** 生成 8 位唯一批次 ID
- **并且** 所有阶段的状态记录关联到该批次
- **并且** 支持按批次 ID 查询历史迁移记录

#### 场景：导入批次策略

- **当** 执行 MySQL 导入阶段
- **那么** 复用现有的 sql_import_log 表进行状态追踪
- **并且** 支持 `--resume` 参数跳过已成功导入的文件
- **并且** 支持 `--retry-failed` 参数只重试失败的文件

---

### 需求：外键提取与导入

系统必须支持从 Oracle SQL 文件提取外键关系并导入到元数据表。

#### 场景：外键信息提取

- **当** 执行 `fk_extract` 阶段
- **那么** 调用 `python -m AIagent.src.sql_import extract-foreignkey-all <source_dir> -o <foreignkey_dir>` 命令
- **并且** 从 Oracle SQL 文件中提取外键约束信息
- **并且** 生成 `*_foreignkeys.json` 文件到指定目录

#### 场景：外键元数据导入

- **当** 执行 `fk_import` 阶段
- **那么** 调用 `python manage.py import_foreignkey_metadata <foreignkey_dir> --prefix <table_prefix>` 命令
- **并且** 将外键 JSON 文件导入到 `table_foreignkey_metadata` 表
- **并且** 自动为表名和约束名添加前缀

#### 场景：外键导入配置

- **当** 启动迁移任务时指定 `--foreignkey-dir <dir>` 参数
- **那么** 使用指定目录存储外键 JSON 文件
- **当** 未指定外键目录
- **那么** 使用默认目录 `docs/hospital/foreignkey/`

#### 场景：表名前缀配置

- **当** 启动迁移任务时指定 `--table-prefix <prefix>` 参数
- **那么** 在外键导入时为所有表名和约束名添加该前缀
- **当** 未指定前缀
- **那么** 使用默认前缀 `gzlry_`

---

### 需求：自然语言交互

系统必须支持用户通过自然语言与智能体进行交互，查询进度、执行操作、获取帮助。

#### 场景：启动交互式对话模式

- **当** 用户执行 `python -m AIagent.src.sql_import.migration_cli chat`
- **那么** 进入交互式对话模式
- **并且** 显示欢迎信息和可用指令提示
- **并且** 等待用户输入自然语言指令

#### 场景：意图识别

- **当** 用户输入自然语言指令
- **那么** 使用 LLM 解析用户意图
- **并且** 识别意图类型（查询/操作/配置/帮助）
- **并且** 提取相关参数

#### 场景：查询类意图处理

- **当** 用户询问进度相关问题（如"当前进度怎么样？"、"有哪些文件失败了？"）
- **那么** 识别为查询意图
- **并且** 调用相应的检查器获取信息
- **并且** 生成友好的中文响应

#### 场景：操作类意图处理

- **当** 用户发出操作指令（如"开始迁移"、"继续任务"、"重试失败的"、"跳过当前阶段"）
- **那么** 识别为操作意图
- **并且** 确认操作（如果是危险操作）
- **并且** 执行对应的命令
- **并且** 返回执行结果

#### 场景：配置类意图处理

- **当** 用户设置配置（如"设置源目录为 xxx"、"使用 xxx 作为上下文文件"）
- **那么** 识别为配置意图
- **并且** 更新迁移状态中的配置
- **并且** 确认配置已更新

#### 场景：帮助意图处理

- **当** 用户请求帮助（如"帮助"、"怎么使用？"、"有什么功能？"）
- **那么** 显示使用说明
- **并且** 列出支持的自然语言指令示例

#### 场景：响应生成

- **当** 完成意图处理
- **那么** 使用 LLM 生成友好的中文响应
- **并且** 包含操作结果和后续建议
- **并且** 保持对话上下文

#### 场景：单次自然语言调用

- **当** 用户执行 `python -m AIagent.src.sql_import.migration_cli ask "<自然语言问题>"`
- **那么** 处理单次自然语言输入
- **并且** 输出响应后退出
- **并且** 不进入交互模式
