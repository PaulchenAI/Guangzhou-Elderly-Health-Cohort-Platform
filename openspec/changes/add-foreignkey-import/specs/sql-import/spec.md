## 新增需求

### 需求：外键关系元数据表

系统必须提供一张表来存储表之间的外键关系信息。

#### 场景：创建元数据表

- **当** 首次运行导入命令
- **那么** 自动创建 `table_foreignkey_metadata` 表
- **并且** 表结构包含：源表名、源字段、目标表名、目标字段、约束名、删除规则、来源文件、创建时间

#### 场景：存储复合外键

- **当** 外键包含多个字段（如 `["PATIENT_ID", "VISIT_ID"]`）
- **那么** 使用 JSON 格式存储字段列表
- **并且** 保持字段顺序

---

### 需求：外键关系元数据批量导入

系统必须支持从 JSON 文件批量导入外键关系信息到元数据表，并自动补全表名前缀。

#### 场景：读取外键 JSON 文件

- **当** 用户指定外键 JSON 文件目录（如 `docs/hospital/foreignkey/`）
- **那么** 系统遍历目录下所有 `*_foreignkeys.json` 文件
- **并且** 解析每个文件中的 `foreign_keys` 数组
- **并且** 跳过 `foreign_keys` 为空的文件

#### 场景：表名前缀补全

- **当** 导入外键关系信息时
- **那么** 源表名添加指定前缀（默认 `gzlry_`）
- **并且** 目标表名添加指定前缀
- **并且** 约束名添加指定前缀
- **例如** `BS_DEPARTMENT` 变为 `gzlry_BS_DEPARTMENT`

#### 场景：插入元数据记录

- **当** 处理单个外键关系
- **那么** 将以下信息插入 `table_foreignkey_metadata` 表：
  - `source_table`：带前缀的源表名
  - `source_columns`：源字段 JSON 数组
  - `target_table`：带前缀的目标表名
  - `target_columns`：目标字段 JSON 数组
  - `constraint_name`：带前缀的约束名
  - `on_delete`：删除规则（如果有）
  - `source_file`：来源 JSON 文件名

#### 场景：预览模式

- **当** 用户使用 `--dry-run` 参数
- **那么** 只显示将要导入的数据
- **并且** 不执行数据库插入操作

#### 场景：清空后导入

- **当** 用户使用 `--truncate` 参数
- **那么** 在导入前清空 `table_foreignkey_metadata` 表
- **并且** 重新导入所有数据

---

### 需求：外键关系元数据导入 Django 命令

系统必须提供 Django management command，支持外键关系元数据的批量导入。

#### 场景：批量导入命令

- **当** 用户执行 `python manage.py import_foreignkey_metadata [json_dir] [options]`
- **那么** 遍历目录下所有外键 JSON 文件并导入到元数据表
- **并且** 支持以下参数：
  - `--prefix <prefix>`：表名前缀（默认 `gzlry_`）
  - `--dry-run`：预览模式
  - `--truncate`：导入前清空表
  - `--verbose`：显示详细进度

#### 场景：显示导入进度

- **当** 批量导入进行中
- **那么** 显示当前进度（已处理/总文件数）
- **并且** 显示当前处理的表名和外键数量

#### 场景：生成导入报告

- **当** 批量导入完成
- **那么** 输出汇总报告：
  - 总文件数
  - 有外键的文件数
  - 总外键关系数
  - 导入成功数
