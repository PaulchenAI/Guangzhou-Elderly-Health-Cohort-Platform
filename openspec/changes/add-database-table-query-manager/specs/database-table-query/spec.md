# 规范：数据库表查询管理

## 新增需求

### 需求：表查询配置管理

系统必须提供表查询配置管理功能，允许管理员通过 JSON 配置定义可查询的数据库表及其字段属性。

#### 场景：创建表查询配置
- **当** 管理员创建新的表查询配置时
- **那么** 系统必须验证 JSON 配置格式的正确性
- **并且** 系统必须验证配置的表名在数据库中存在
- **并且** 系统必须验证配置的字段名在表中存在
- **并且** 配置必须包含 `table_name`、`display_name`、`fields` 等必需字段
- **并且** 配置保存后自动激活

#### 场景：更新表查询配置
- **当** 管理员更新现有配置时
- **那么** 系统必须重新验证配置的有效性
- **并且** 更新后的配置立即生效
- **并且** 记录配置变更历史

#### 场景：删除表查询配置
- **当** 管理员删除配置时
- **那么** 系统必须软删除配置（设置 `is_active=False`）
- **并且** 相关菜单项自动隐藏
- **并且** 保留历史查询记录

#### 场景：配置验证失败
- **当** 配置的表名不存在或字段无效时
- **那么** 系统必须返回详细的错误信息
- **并且** 不允许保存无效配置

### 需求：动态表查询 API

系统必须提供通用的表查询 API，根据配置动态查询数据库表，支持分页、过滤和排序。

#### 场景：基础查询
- **当** 用户请求查询某个配置的表时
- **那么** 系统必须返回该表的数据，只包含配置中 `visible=true` 的字段
- **并且** 默认使用配置的 `default_page_size` 进行分页
- **并且** 默认使用配置的 `default_order_by` 进行排序
- **并且** 返回总记录数和当前页码

#### 场景：带过滤条件的查询
- **当** 用户提供过滤条件时
- **那么** 系统必须只对配置中 `searchable=true` 的字段进行过滤
- **并且** 支持的操作符包括：`=`, `!=`, `>`, `<`, `>=`, `<=`, `LIKE`, `IN`, `BETWEEN`
- **并且** 多个过滤条件使用 AND 逻辑连接
- **并且** 拒绝非法的过滤字段和操作符

#### 场景：自定义排序
- **当** 用户指定排序字段时
- **那么** 系统必须验证排序字段在配置中 `sortable=true`
- **并且** 支持升序（ASC）和降序（DESC）
- **并且** 拒绝非法的排序字段

#### 场景：分页查询
- **当** 用户指定页码和每页大小时
- **那么** 系统必须返回对应页的数据
- **并且** 每页大小不能超过配置的 `max_page_size`
- **并且** 返回分页元数据（总页数、总记录数、当前页、每页大小）

#### 场景：查询权限验证
- **当** 用户发起查询请求时
- **那么** 系统必须验证用户是否有该表的查询权限
- **并且** 未授权的用户必须返回 403 错误
- **并且** 记录查询操作日志

#### 场景：查询性能保护
- **当** 查询请求可能导致性能问题时
- **那么** 系统必须强制分页，拒绝无分页的全表查询
- **并且** 单次查询记录数不能超过 `max_page_size`
- **并且** 对于超大表（>100万条记录），返回性能警告

### 需求：SQL 注入防护

系统必须防止 SQL 注入攻击，确保查询安全。

#### 场景：表名验证
- **当** 构建查询 SQL 时
- **那么** 系统必须验证表名在配置白名单中
- **并且** 拒绝包含特殊字符的表名
- **并且** 使用参数化查询或转义表名

#### 场景：字段名验证
- **当** 处理查询字段、过滤字段、排序字段时
- **那么** 系统必须验证字段名在配置白名单中
- **并且** 拒绝包含特殊字符或 SQL 关键字的字段名
- **并且** 不允许字段名包含空格、分号、注释符等危险字符

#### 场景：参数值验证
- **当** 处理用户输入的过滤值时
- **那么** 系统必须使用参数化查询传递值
- **并且** 验证值的数据类型与字段类型匹配
- **并且** 限制字符串值的长度（最大 1000 字符）
- **并且** 拒绝包含 SQL 注释符（`--`, `/*`, `*/`）的输入

#### 场景：操作符验证
- **当** 处理过滤条件的操作符时
- **那么** 系统必须验证操作符在白名单中
- **并且** 白名单包括：`=`, `!=`, `>`, `<`, `>=`, `<=`, `LIKE`, `IN`, `BETWEEN`, `IS NULL`, `IS NOT NULL`
- **并且** 拒绝任何其他操作符或 SQL 关键字

### 需求：数据导出功能

系统必须支持将查询结果导出为文件格式，方便用户下载和分析。

#### 场景：导出为 Excel
- **当** 用户请求导出数据为 Excel 格式时
- **那么** 系统必须生成 `.xlsx` 文件
- **并且** 文件包含当前查询条件下的所有数据（不限于当前页）
- **并且** 导出记录数不能超过 10,000 条（性能限制）
- **并且** 字段名使用配置的 `display_name`

#### 场景：导出为 CSV
- **当** 用户请求导出数据为 CSV 格式时
- **那么** 系统必须生成 `.csv` 文件
- **并且** 使用 UTF-8 编码
- **并且** 字段使用逗号分隔，字符串使用双引号包裹

#### 场景：导出权限验证
- **当** 用户请求导出数据时
- **那么** 系统必须验证用户是否有导出权限
- **并且** 配置的 `allowed_operations` 必须包含 `export`
- **并且** 记录导出操作日志（用户、表名、导出时间、记录数）

#### 场景：导出数量限制
- **当** 导出数据量超过限制时
- **那么** 系统必须返回错误提示
- **并且** 建议用户使用过滤条件缩小范围
- **或者** 提供异步导出功能（大数据量）

### 需求：前端表查询页面

系统必须提供友好的前端页面，支持表切换、条件查询和数据展示。

#### 场景：表选择
- **当** 用户打开表查询页面时
- **那么** 显示所有可用表的列表（下拉或侧边栏）
- **并且** 列表显示配置的 `display_name` 和 `description`
- **并且** 默认选中第一个表
- **并且** 切换表时自动清空当前查询条件

#### 场景：动态查询表单
- **当** 用户选择某个表时
- **那么** 根据表配置动态生成查询表单
- **并且** 只显示 `searchable=true` 的字段
- **并且** 根据字段类型生成对应的输入组件（文本框、日期选择器、下拉框等）
- **并且** 支持多个条件组合查询

#### 场景：数据展示
- **当** 查询成功返回数据时
- **那么** 使用表格展示数据
- **并且** 表头显示配置的 `display_name`
- **并且** 支持列排序（点击表头）
- **并且** 支持前端分页或后端分页
- **并且** 显示总记录数和当前页码

#### 场景：数据导出
- **当** 用户点击导出按钮时
- **那么** 弹出格式选择对话框（Excel/CSV）
- **并且** 导出当前查询条件下的数据
- **并且** 显示导出进度
- **并且** 导出完成后自动下载文件

#### 场景：查询错误处理
- **当** 查询失败时
- **那么** 显示友好的错误提示
- **并且** 区分不同错误类型（权限错误、参数错误、服务器错误）
- **并且** 提供重试按钮

### 需求：菜单初始化脚本

系统必须提供菜单初始化脚本，自动为表查询配置生成菜单项。

#### 场景：初始化表查询菜单
- **当** 执行菜单初始化命令时
- **那么** 系统必须创建"数据查询"父菜单（如不存在）
- **并且** 为每个激活的表查询配置创建子菜单
- **并且** 子菜单名称使用配置的 `display_name`
- **并且** 子菜单路由指向表查询页面，并传递配置 ID

#### 场景：更新已有菜单
- **当** 表查询配置更新时（名称变更）
- **那么** 执行初始化命令必须更新对应菜单项
- **并且** 不会创建重复的菜单

#### 场景：删除无效菜单
- **当** 表查询配置被删除或禁用时
- **那么** 执行初始化命令必须隐藏或删除对应菜单项

### 需求：配置管理 API

系统必须提供配置管理 API，允许管理员通过接口管理表查询配置。

#### 场景：获取配置列表
- **当** 管理员请求配置列表时
- **那么** 返回所有表查询配置（支持分页）
- **并且** 支持按表名、显示名称搜索
- **并且** 支持按激活状态过滤

#### 场景：获取配置详情
- **当** 管理员请求某个配置的详情时
- **那么** 返回完整的配置 JSON
- **并且** 包含创建时间、更新时间、创建人等元数据

#### 场景：创建配置
- **当** 管理员提交新配置时
- **那么** 系统必须验证配置格式
- **并且** 验证表和字段的有效性
- **并且** 保存配置并返回配置 ID

#### 场景：更新配置
- **当** 管理员更新配置时
- **那么** 系统必须验证新配置的有效性
- **并且** 保存更新并记录变更历史

#### 场景：删除配置
- **当** 管理员删除配置时
- **那么** 系统必须软删除（设置 `is_active=False`）
- **并且** 返回删除成功消息

#### 场景：批量导入配置
- **当** 管理员上传配置文件（JSON/YAML）时
- **那么** 系统必须验证每个配置的有效性
- **并且** 批量创建或更新配置
- **并且** 返回导入结果报告（成功数、失败数、错误详情）

### 需求：操作审计日志

系统必须记录表查询相关的操作日志，用于安全审计。

#### 场景：记录查询操作
- **当** 用户执行表查询时
- **那么** 系统必须记录日志，包含：用户、表名、查询条件、查询时间、返回记录数
- **并且** 日志保存到数据库或日志文件

#### 场景：记录导出操作
- **当** 用户导出数据时
- **那么** 系统必须记录日志，包含：用户、表名、导出格式、导出记录数、导出时间
- **并且** 高优先级记录（可能涉及敏感数据导出）

#### 场景：记录配置变更
- **当** 管理员创建、更新或删除配置时
- **那么** 系统必须记录配置变更日志
- **并且** 包含变更前后的配置内容（JSON diff）

#### 场景：日志查询
- **当** 管理员查询操作日志时
- **那么** 支持按用户、表名、操作类型、时间范围过滤
- **并且** 支持导出日志数据

### 需求：权限控制

系统必须集成现有的 RBAC 权限系统，对表查询功能进行权限控制。

#### 场景：配置管理权限
- **当** 用户访问配置管理 API 时
- **那么** 系统必须验证用户是否有"表查询配置管理"权限
- **并且** 只有管理员角色才能管理配置

#### 场景：表查询权限
- **当** 用户查询某个表时
- **那么** 系统必须验证用户是否有该表的查询权限
- **并且** 权限可以按表粒度配置
- **并且** 未授权用户返回 403 错误

#### 场景：数据导出权限
- **当** 用户导出数据时
- **那么** 系统必须验证用户是否有导出权限
- **并且** 导出权限独立于查询权限
- **并且** 可以限制某些用户只能查看不能导出

#### 场景：菜单权限
- **当** 用户访问系统菜单时
- **那么** 只显示用户有权限访问的表查询菜单项
- **并且** 无权限的菜单项自动隐藏
