## 新增需求

### 需求：SQL 语法自动修复

系统必须提供自动修复 SQL 语法错误的能力，特别是针对 MySQL 保留字冲突问题。

#### 场景：检测并修复 MySQL 保留字

- **当** SQL 文件中的列名或表名使用了 MySQL 保留字（如 `describe`、`key`、`condition`）
- **那么** 自动在这些标识符两边添加反引号包裹
- **并且** 只修复 CREATE TABLE 和 INSERT INTO 语句中的保留字
- **并且** 不修复字符串字面量内的保留字

#### 场景：启用自动修复

- **当** 用户使用 `--auto-fix` 参数导入 SQL 文件
- **那么** 系统在执行 SQL 前自动修复语法错误
- **并且** 修复过程在内存中进行，不修改源文件

#### 场景：保存修复后的 SQL

- **当** 用户使用 `--save-fixed` 参数
- **那么** 将修复后的 SQL 保存到新文件
- **并且** 新文件名添加 `_fixed` 后缀（如 `table.sql` → `table_fixed.sql`）

#### 场景：生成修复报告

- **当** 用户使用 `--fix-report` 参数
- **那么** 生成详细的修复报告，记录所有修复的位置和内容
- **并且** 报告包含：文件名、行号、修复前后对比、修复类型

#### 场景：修复失败提示

- **当** 导入失败且系统检测到可能的 MySQL 保留字问题
- **那么** 提示用户使用 `--auto-fix` 参数重试
- **并且** 显示具体的错误信息和修复建议

#### 场景：安全修复边界

- **当** 执行自动修复时
- **那么** 只修复明确的语法错误，不改变 SQL 语义
- **并且** 不修复已用反引号包裹的标识符
- **并且** 不修复注释内的保留字

## 修改需求

### 需求：批量 SQL 文件导入

系统必须支持批量导入转换后的 MySQL SQL 文件到数据库。

#### 场景：读取转换后的文件

- **当** 用户指定转换后的 SQL 文件或目录
- **那么** 系统读取文件内容并执行 SQL 语句

#### 场景：指定目录导入

- **当** 用户指定 `docs/hospital/convertsql/` 目录并使用 `--all` 参数
- **那么** 系统遍历目录下所有 `.sql` 文件并依次导入

#### 场景：导入成功

- **当** SQL 文件执行成功
- **那么** 记录成功日志，继续处理下一个文件

#### 场景：导入失败

- **当** SQL 文件执行失败（语法错误、约束冲突等）
- **那么** 记录错误日志（文件名、错误信息），根据 `--continue-on-error` 参数决定是否继续
- **并且** 如果启用了 `--auto-fix` 参数，尝试自动修复后重试

#### 场景：预览模式

- **当** 用户使用 `--dry-run` 参数
- **那么** 仅显示 SQL 内容，不执行数据库操作

#### 场景：外键检查处理

- **当** 导入 SQL 文件时
- **那么** 自动禁用外键检查（`SET FOREIGN_KEY_CHECKS = 0`），导入完成后恢复
