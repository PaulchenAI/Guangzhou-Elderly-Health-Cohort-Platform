## 修改需求

### 需求：同步 API 端点

系统必须提供 `POST /api/core/survey/sync` API 端点，支持手动触发问卷数据同步。

#### 场景：调用同步 API

- **当** 前端发送 POST 请求到 `/api/core/survey/sync`
- **那么** 后端调用 `SurveyService.import_data()` 执行数据同步
- **并且** 返回同步结果（batch_id、total、success、skipped、failed）
- **并且** 导入日志的 `trigger_type` 记录为 `manual`
- **并且** 如果启用了表查询系统同步，数据同步成功后自动同步到表查询系统

#### 场景：支持指定问卷类型同步

- **当** 请求参数包含 `survey_type` 字段
- **那么** 只同步指定类型的问卷数据
- **当** 请求参数不包含 `survey_type` 字段
- **那么** 同步所有类型的问卷数据

## 新增需求

### 需求：问卷数据同步到表查询系统

系统必须在同步问卷数据时，自动将数据同步到表查询系统，以便统一数据查询体验。

#### 场景：自动同步到表查询系统

- **当** 问卷数据导入成功后
- **那么** 系统自动将数据展开并同步到对应的表查询表（`survey_{survey_type}`）
- **并且** 如果表不存在，自动创建表和配置
- **并且** 如果表已存在，更新或插入数据
- **并且** 同步过程记录在导入日志中

#### 场景：JSON 字段展开

- **当** 同步问卷数据到表查询系统时
- **那么** 系统将 JSON 字段（survey_data、patient_info、scores 等）展开为关系型表的列
- **并且** 对象类型字段展开为 `{field}_{key}` 格式（如 `survey_data_totalScore`）
- **并且** 嵌套对象递归展开（如 `personalityScores.totalScore` → `personalityScores_totalScore`）
- **并且** 保留原始 JSON 字段用于完整数据查询
- **并且** 展开逻辑参考前端 `expandJsonFields` 函数

#### 场景：根据问卷类型创建表

- **当** 同步不同问卷类型的数据时
- **那么** 系统为每个问卷类型创建对应的表（如 `survey_personality`、`survey_outdoor_activity`）
- **并且** 表名格式为 `survey_{survey_type}`
- **并且** 表结构包含展开后的字段和原始 JSON 字段
- **并且** 自动创建必要的索引（survey_id、patient_name、record_time 等）

#### 场景：自动生成表查询配置

- **当** 创建新的问卷类型表时
- **那么** 系统自动创建对应的 `TableQueryConfig` 配置
- **并且** 配置包含表名、显示名称（问卷名称）、字段定义
- **并且** 字段配置包含字段名、显示名称、类型、可搜索、可排序、可见性属性
- **并且** 字段类型根据 JSON 值类型和 Schema 配置推断

#### 场景：支持配置同步选项

- **当** 调用同步 API 时
- **那么** 请求参数可以包含 `sync_to_table_query` 字段（默认为 `true`）
- **当** `sync_to_table_query` 为 `true`
- **那么** 数据同步成功后自动同步到表查询系统
- **当** `sync_to_table_query` 为 `false`
- **那么** 只同步到问卷系统，不同步到表查询系统

#### 场景：同步错误处理

- **当** 表查询系统同步失败时
- **那么** 系统记录错误信息到导入日志
- **并且** 问卷数据同步不受影响（已成功导入到问卷系统）
- **并且** 返回同步结果时包含表查询系统同步状态
- **并且** 用户可以手动触发重新同步
