# 设计：问卷数据同步到表查询系统

## 上下文

### 现状
- **问卷系统**：数据存储在 `SurveyRecord` 模型中，使用 JSON 字段（survey_data, patient_info, scores 等）
- **表查询系统**：需要手动创建 `TableQueryConfig` 配置，支持动态查询数据库表
- **数据查询**：两个系统独立，无法联合查询

### 约束
- 需要保持问卷系统的现有功能不变
- 表查询系统需要支持动态表结构
- JSON 数据需要展开为关系型表结构
- 需要处理不同问卷类型的差异

## 目标 / 非目标

### 目标
- 将问卷数据自动同步到表查询系统
- 根据问卷类型创建对应的表
- JSON 字段展开为关系型表的列
- 支持增量同步和全量同步
- 自动生成表查询配置

### 非目标
- 不改变问卷系统的现有数据模型
- 不改变表查询系统的核心查询逻辑
- 不强制要求所有问卷类型都同步（可配置）

## 决策

### 决策 1：表命名规范
**决策**：使用 `survey_{survey_type}` 作为表名（如 `survey_personality`, `survey_outdoor_activity`）

**理由**：
- 清晰标识数据来源
- 避免与现有表名冲突
- 便于管理和查询

**考虑的替代方案**：
- 使用问卷名称作为表名：可能包含特殊字符，需要转义
- 使用 UUID：不便于识别和管理

### 决策 2：JSON 字段展开策略
**决策**：参考前端 `expandJsonFields` 函数的逻辑，将 JSON 对象展开为 `{jsonField}_{key}` 格式的列

**理由**：
- 与前端展示逻辑一致
- 支持嵌套结构（如 `personalityScores.totalScore` → `personalityScores_totalScore`）
- 保留原始 JSON 字段用于完整数据查询

**展开规则**：
- 对象类型：展开为 `{field}_{key}` 格式
- 数组类型：如果数组元素是对象，展开为多行（需要关联表）；如果是简单类型，存储为 JSON
- 嵌套对象：递归展开，使用 `_` 连接层级

**考虑的替代方案**：
- 完全扁平化：可能产生过多列，难以管理
- 保持 JSON 格式：无法利用关系型数据库的查询优势

### 决策 3：字段类型推断
**决策**：根据 JSON 值的类型和 Schema 配置推断字段类型

**推断规则**：
- 字符串：检查是否为日期时间格式，如果是则为 `datetime`，否则为 `string`
- 数字：整数为 `integer`，小数为 `decimal`
- 布尔值：`boolean`
- 对象/数组：保持为 JSON 类型，但展开的字段根据实际值推断

**理由**：
- 支持表查询系统的类型化查询
- 提高查询性能（索引、排序等）

### 决策 4：同步时机
**决策**：在 `SurveyService.import_data()` 方法中，数据导入成功后立即同步到表查询系统

**理由**：
- 保证数据一致性
- 减少重复处理
- 利用现有的事务机制

**流程**：
1. 导入问卷数据到 `SurveyRecord`
2. 展开 JSON 字段
3. 插入/更新到对应的表查询表
4. 如果表不存在，自动创建表和配置

### 决策 5：配置自动生成
**决策**：根据问卷 Schema 自动生成 `TableQueryConfig` 配置

**配置内容**：
- `table_name`：`survey_{survey_type}`
- `display_name`：问卷名称
- `fields`：从 Schema 和实际数据推断的字段列表
- `default_page_size`：20
- `max_page_size`：100

**字段配置**：
- `name`：展开后的字段名
- `display_name`：从 Schema 或字段名推断的中文名称
- `type`：推断的字段类型
- `searchable`：从 Schema 中获取，默认为 `true`
- `sortable`：默认为 `true`
- `visible`：默认为 `true`

## 风险 / 权衡

### 风险 1：数据一致性
**风险**：问卷数据更新后，表查询系统的数据可能不同步

**缓解措施**：
- 在同步时记录同步时间戳
- 支持手动触发重新同步
- 提供数据一致性检查工具

### 风险 2：表结构变更
**风险**：问卷 Schema 变更后，表结构需要更新

**缓解措施**：
- 检测 Schema 变更，自动添加新字段
- 保留旧字段，标记为已废弃
- 提供表结构迁移工具

### 风险 3：性能影响
**风险**：大量数据同步可能影响系统性能

**缓解措施**：
- 使用批量插入
- 异步处理（可选）
- 支持分页同步
- 添加索引优化查询

### 风险 4：存储空间
**风险**：展开后的数据可能占用更多存储空间

**权衡**：
- 展开后的数据便于查询和索引
- 可以只同步常用字段，其他字段保持 JSON 格式
