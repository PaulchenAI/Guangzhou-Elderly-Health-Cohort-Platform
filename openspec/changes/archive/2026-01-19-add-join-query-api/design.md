# 外键联合查询 API 技术设计

## 上下文

### 背景
系统已有两个相关功能：
1. **foreignkey-api**：存储和查询外键关系元数据（`table_foreignkey_metadata` 表）
2. **database-table-query**：动态单表查询功能

用户需要根据外键关系自动进行多表联合查询，将主表与其关联表的数据合并输出。

### 约束
- 必须复用现有的外键元数据
- 需要防止 SQL 注入
- 需要控制查询复杂度和性能
- 支持现有的表查询配置体系

## 目标 / 非目标

### 目标
- 提供 API 根据外键关系自动构建 JOIN 查询
- 支持多级关联（可配置深度限制）
- 只查询主表的出向关系（主表引用的表）
- 使用 LEFT JOIN 保证主表数据完整
- 自动处理字段名冲突
- 支持分页、过滤、排序
- 支持数据导出

### 非目标
- 不支持入向关系查询（被引用）
- 不支持自定义 JOIN 条件（只使用外键定义的关系）
- 不支持聚合查询

## 决策

### 1. 关联关系解析策略

**决策**：使用递归方式从 `table_foreignkey_metadata` 表解析关联关系树

**考虑的替代方案**：
- 预计算关联图并缓存 → 增加复杂度，数据同步问题
- 每次查询实时解析 → 简单直接，选择此方案

### 2. SQL 构建策略

**决策**：动态构建带 LEFT JOIN 的 SQL 语句

```sql
SELECT 
    主表.字段1 AS 主表_字段1,
    关联表1.字段1 AS 关联表1_字段1,
    关联表2.字段1 AS 关联表2_字段1
FROM 主表
LEFT JOIN 关联表1 ON 主表.外键字段 = 关联表1.主键字段
LEFT JOIN 关联表2 ON 关联表1.外键字段 = 关联表2.主键字段
WHERE ...
ORDER BY ...
LIMIT ... OFFSET ...
```

**字段别名规则**：`{表名}_{字段名}`，避免冲突

### 3. 关联深度控制

**决策**：
- 默认最大深度：3 级
- 可通过参数调整，上限 5 级
- 超过深度限制的关联自动忽略

### 4. 性能保护措施

**决策**：
- 默认分页大小：20
- 最大分页大小：100
- 最大关联表数量：10
- 查询超时设置：30 秒

## 数据流

```
请求 → 验证参数 → 解析主表配置
                    ↓
              从外键元数据获取关联关系
                    ↓
              构建关联关系树（控制深度）
                    ↓
              构建 SELECT 字段列表（加前缀）
                    ↓
              构建 LEFT JOIN 子句
                    ↓
              构建 WHERE 子句（验证字段）
                    ↓
              执行 SQL 查询
                    ↓
              返回分页结果
```

## API 设计

### 联合查询端点

```
POST /api/core/table-query/join-query
```

**请求体**：
```json
{
    "primary_table": "主表名或配置名",
    "max_depth": 2,
    "include_tables": ["可选：指定要包含的关联表"],
    "exclude_tables": ["可选：指定要排除的关联表"],
    "page": 1,
    "page_size": 20,
    "filters": [
        {"field": "主表_字段名", "operator": "eq", "value": "值"}
    ],
    "order_by": "主表_字段名 DESC"
}
```

**响应**：
```json
{
    "items": [...],
    "total": 100,
    "page": 1,
    "page_size": 20,
    "join_info": {
        "primary_table": "主表名",
        "joined_tables": ["关联表1", "关联表2"],
        "join_depth": 2
    }
}
```

### 关联关系预览端点

```
GET /api/core/table-query/join-preview/{table_name}?max_depth=2
```

用于预览某个表的关联关系，帮助用户了解可用的关联。

## 风险 / 权衡

| 风险 | 缓解措施 |
|------|----------|
| 多表 JOIN 性能问题 | 限制关联深度和表数量，分页查询 |
| 循环引用导致无限递归 | 记录已访问表，检测循环 |
| 字段名冲突 | 统一加表名前缀 |
| SQL 注入 | 参数化查询，白名单验证 |
