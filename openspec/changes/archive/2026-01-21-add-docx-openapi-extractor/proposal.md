# 变更：新增 DOCX API 文档解析与 OpenAPI 3.x 导出智能体

## 为什么

当前项目存在大量以 Word（`.docx`）形式维护的接口规范文档（例如 `docs/his/数据中台大临床服务规范-DVE版V1.1---养老队列系统.docx`）。这些文档包含接口名称、请求方式/路径、入参/出参表、示例请求/响应等信息，但无法被程序直接理解与消费，导致：

- API 能力无法被智能体/工具链直接利用（例如自动生成调用脚本、参数校验、文档同步）。
- 维护成本高：接口变更后需要手工同步到 OpenAPI/Swagger 等机器可读格式。
- 质量不可控：缺字段、格式不一致时难以自动发现与纠正。

因此需要基于 `@AIagent` 框架提供一个 LLM Agent，将 `.docx` 接口文档解析为 **OpenAPI 3.x JSON**，并覆盖 **接口信息 + 入参/出参 + 示例**（A+B+C），以便后续自动化集成与验证。

## 变更内容

- 新增 `DocxOpenAPIExtractorAgent`（命名仅为提案建议，实施阶段可调整），支持从 `.docx` 文档解析接口定义并导出 **OpenAPI 3.x JSON**。
- 定义稳定的解析与归一化规则：
  - 接口识别与切分（按“接口名称/编号”等结构化标记或稳定模式）
  - HTTP 方法、path 解析
  - 入参/出参表格解析为 schema/parameters/response schema
  - 示例请求/响应提取与映射（`examples` / `requestBody` / `responses`）
- 提供 CLI 用法（导出、校验、预览差异等）与可重复的输出产物。
- 对输出 OpenAPI 做结构校验，并在解析失败或缺失关键字段时给出可操作的错误报告（包含定位到文档位置的线索）。

## 影响

- 受影响规范：新增 `api-doc-extractor`（本变更提案中引入的能力规范）
- 受影响代码（实施阶段）：`AIagent/src/` 将新增解析器、生成器、Agent 与 CLI 入口（不在本提案阶段编写代码）
- 受影响文档：将新增使用说明与一个可复现的示例导出产物（可选）
