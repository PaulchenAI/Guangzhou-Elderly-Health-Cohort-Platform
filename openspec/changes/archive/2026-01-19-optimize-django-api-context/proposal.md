# 变更：优化 Django API 上下文管理

## 为什么

当前 Django API 智能体在初始化时加载所有 288 个 API 端点到上下文中，随着 API 数量增长，可能导致 AI 上下文窗口超限。同时，生成的脚本没有持久化保存，无法作为 RAG 知识库供后续复用。

## 变更内容

### 1. API 上下文优化
- 实现 API 端点分层摘要机制，避免一次性加载全部端点详情
- 第一层：仅加载 API 分类（Tags）和端点数量统计
- 第二层：按需加载特定 Tag 下的端点摘要
- 第三层：仅在 LLM 选择后加载完整端点详情
- 配置化控制：支持设置上下文 Token 限制阈值

### 2. 历史指令 RAG 检索与复用
- **强制优先检索**：每次新指令必须先检索历史相似指令
- **成功/失败全记录**：所有执行记录（成功和失败）都必须保存
- **失败原因学习**：失败记录包含错误信息，避免重复同样的错误
- **成功脚本复用**：相似指令直接参考历史成功脚本
- 为生成的脚本配置默认保存目录（如 `data/execution_history/`）
- 按日期和意图分类保存脚本文件
- 保存完整元数据（意图、API、执行结果、错误信息、时间戳）
- **自动保存集成**：在 `cmd_generate` 中集成执行历史保存逻辑，默认启用（可通过 `--no-save` 禁用）

### 3. 查询结果默认翻页
- **默认翻页参数**：查询没有明确数目时，自动添加翻页参数
- 默认 `page=1`，`pageSize=10`（可配置）
- 避免一次性返回大量数据导致超时或内存溢出

### 4. 用户体验优化
- **自动迭代修正默认启用**：`--auto-fix` 参数默认启用，提高脚本生成成功率
- **修复参数错误**：修复 `ScriptGenerator` 初始化时的不支持参数错误
- **执行历史自动保存**：每次执行后自动保存记录，无需手动操作

### 5. 验证阶段智能修正
- **操作符格式说明**：在 LLM 提示词中明确支持的操作符格式（`eq`, `ne`, `like` 等），避免 LLM 使用无效符号（`=`, `==`, `!=`）
- **配置名保留机制**：修正阶段强制保留已验证的配置名，防止 LLM 错误修改
- **字段名映射表**：提供字段名（英文）与显示名（中文）的映射表，帮助 LLM 正确选择字段
- **无效 HTTP 方法检测**：跳过 `NONE` 等无效 HTTP 方法，避免运行时崩溃
- **路径参数传递**：正确传递 `path_params` 参数，支持 URL 路径中的变量替换

## 影响

- 受影响规范：`aiagent`
- 受影响代码：
  - `AIagent/src/django_api/client.py` - API 摘要生成
  - `AIagent/src/django_api/agent.py` - 上下文管理
  - `AIagent/src/django_api/script_generator.py` - 脚本持久化
  - `AIagent/src/django_api/retriever.py` - 脚本 RAG 检索
  - `AIagent/src/django_api/cli.py` - CLI 参数和保存逻辑集成
