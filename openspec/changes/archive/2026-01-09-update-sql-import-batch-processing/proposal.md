# 变更：优化 SQL 导入命令支持大文件批量导入、事务管理和自动修复

## 为什么

当前的 `import_oracle_sql` 命令虽然支持批量导入目录下的 SQL 文件，但存在以下关键问题：

1. **数据完整性风险**：没有事务管理和状态追踪，导入一半失败无法回滚或继续，可能导致数据缺漏或重复
2. **内存占用问题**：一次性读取整个 SQL 文件到内存，对于大文件（如 2.7GB）可能导致内存溢出
3. **用户体验不明确**：缺少断点续导、失败重试等功能
4. **MySQL 语法兼容性**：转换后的 SQL 可能包含 MySQL 保留字，需要手动修复

## 变更内容

### 核心改进
- **事务管理**：每个文件作为一个事务单元，失败自动回滚
- **状态追踪**：创建 `sql_import_log` 表记录每个文件的导入状态
- **断点续导**：支持 `--resume` 参数继续未完成的导入
- **失败重试**：支持 `--retry-failed` 参数只重试失败的文件
- **防止重复**：三重防护机制（状态表 + 唯一键 + 批次隔离）

### 性能优化
- **流式读取**：对大文件（>10MB）使用流式读取，避免内存溢出
- **文件过滤**：支持 `--skip-large-files` 和 `--max-size` 参数跳过超大文件
- **智能排序**：按文件大小排序，优先处理小文件

### 用户体验
- **快捷参数**：`--default-convertsql` 自动导入转换目录
- **状态查看**：`--show-status` 查看导入历史和详细状态
- **进度显示**：显示文件大小、语句数量、耗时等信息
- **智能路径**：自动查找 `docs/hospital/convertsql` 目录

### 自动修复（新增）
- **SQL 语法修复**：`--auto-fix` 自动修复 MySQL 保留字问题
- **修复报告**：`--fix-report` 生成详细的修复报告
- **保存修复文件**：`--save-fixed` 保存修复后的 SQL 文件
- **修复建议**：失败时提示可修复的问题和修复命令

## 影响

- 受影响规范：`sql-import`
- 受影响代码：
  - `backend-django/core/management/commands/import_oracle_sql.py`（主要改进）
  - `backend-django/core/management/commands/sql_syntax_fixer.py`（集成）
  - `backend-django/core/migrations/0002_sql_import_log.py`（新增）
- 兼容性：**完全向后兼容**，所有原有用法保持不变
- 性能影响：< 5%（事务和状态记录的轻微开销）
- 数据库：新增 `sql_import_log` 表用于状态追踪

## 重大变更

**无破坏性变更**。所有新功能通过可选参数提供，原有命令用法完全保持兼容。
