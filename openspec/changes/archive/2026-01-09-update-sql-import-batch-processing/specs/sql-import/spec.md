## 修改需求

### 需求：批量 SQL 文件导入

系统必须支持批量导入转换后的 MySQL SQL 文件到数据库，包括对大文件的优化处理、事务管理和状态追踪。

#### 场景：读取转换后的文件

- **当** 用户指定转换后的 SQL 文件或目录
- **那么** 系统读取文件内容并执行 SQL 语句

#### 场景：指定目录导入

- **当** 用户指定 `docs/hospital/convertsql/` 目录并使用 `--all` 参数
- **那么** 系统遍历目录下所有 `.sql` 文件并依次导入

#### 场景：快捷导入转换目录

- **当** 用户使用 `--default-convertsql` 参数
- **那么** 系统自动导入 `docs/hospital/convertsql/` 目录下所有文件，无需手动指定路径

#### 场景：导入成功

- **当** SQL 文件执行成功
- **那么** 记录成功日志，继续处理下一个文件

#### 场景：导入失败

- **当** SQL 文件执行失败（语法错误、约束冲突等）
- **那么** 记录错误日志（文件名、错误信息），根据 `--continue-on-error` 参数决定是否继续

#### 场景：预览模式

- **当** 用户使用 `--dry-run` 参数
- **那么** 仅显示 SQL 内容（前 1000 字符），不执行数据库操作

#### 场景：外键检查处理

- **当** 导入 SQL 文件时
- **那么** 自动禁用外键检查（`SET FOREIGN_KEY_CHECKS = 0`），导入完成后恢复

#### 场景：流式读取大文件

- **当** 导入大文件（> 10MB）时
- **那么** 使用流式逐行读取，而非一次性加载整个文件到内存
- **并且** 避免内存溢出问题

#### 场景：过滤超大文件

- **当** 用户使用 `--max-size` 参数（例如：`--max-size 100`，单位 MB）
- **那么** 自动跳过超过指定大小的文件
- **并且** 在日志中记录跳过的文件名和大小

#### 场景：自动跳过超大文件

- **当** 用户使用 `--skip-large-files` 参数
- **那么** 自动跳过超过 100MB 的文件
- **并且** 在日志中记录跳过的文件列表

#### 场景：文件级事务管理

- **当** 导入单个文件时
- **那么** 使用数据库事务包裹所有 DML 语句（INSERT、UPDATE、DELETE）
- **并且** 如果任何语句失败，自动回滚该文件的所有更改
- **并且** 如果所有语句成功，自动提交事务

#### 场景：DDL 语句特殊处理

- **当** SQL 文件包含 DDL 语句（CREATE TABLE、ALTER TABLE 等）
- **那么** 将 DDL 和 DML 语句分离
- **并且** DDL 语句不使用事务（因为会导致隐式提交）
- **并且** 先执行 DDL，再执行 DML（使用事务）

#### 场景：超大文件禁用事务

- **当** 用户使用 `--no-transaction` 参数
- **那么** 禁用事务管理
- **并且** 适用于超大文件避免事务超时

## 新增需求

### 需求：导入状态追踪

系统必须记录每个文件的导入状态，支持断点续导和失败重试。

#### 场景：创建状态追踪表

- **当** 首次运行导入命令时
- **那么** 自动创建 `sql_import_log` 表
- **并且** 表结构包含：文件名、文件路径、文件大小、状态、错误信息、开始时间、结束时间、批次ID、语句数量

#### 场景：记录导入状态

- **当** 开始导入文件时
- **那么** 记录状态为 `processing`
- **当** 导入成功时
- **那么** 更新状态为 `success`，记录语句数量和结束时间
- **当** 导入失败时
- **那么** 更新状态为 `failed`，记录错误信息和结束时间
- **当** 跳过文件时
- **那么** 记录状态为 `skipped`，记录跳过原因

#### 场景：批次管理

- **当** 启动新的导入任务时
- **那么** 生成唯一的批次ID（8位UUID）
- **并且** 所有文件的状态记录都关联到该批次ID

#### 场景：查看导入状态

- **当** 用户使用 `--show-status` 参数
- **那么** 显示最近10个批次的统计信息
- **当** 用户使用 `--show-status --batch-id <ID>` 参数
- **那么** 显示指定批次的详细文件列表和状态

#### 场景：断点续导

- **当** 用户使用 `--resume` 参数
- **那么** 自动跳过状态为 `success` 的文件
- **并且** 只导入 `pending` 和 `failed` 状态的文件

#### 场景：重试失败文件

- **当** 用户使用 `--retry-failed` 参数
- **那么** 只重新导入上次失败的文件（状态为 `failed`）
- **并且** 跳过所有成功和待处理的文件

#### 场景：强制重新导入

- **当** 用户使用 `--force` 参数
- **那么** 忽略状态表记录
- **并且** 重新导入所有文件（适用于数据更新场景）

#### 场景：防止重复导入

- **当** 同一批次中文件已成功导入
- **那么** 自动跳过该文件
- **并且** 避免数据重复插入
- **当** 不同批次中导入相同文件
- **那么** 依赖数据库的唯一键约束防止重复数据
- **并且** 忽略 `Duplicate entry` 错误

## 修改需求

### 需求：导入进度与报告

系统必须提供导入进度显示和最终报告，包括文件大小信息、语句数量和时间统计。

#### 场景：显示进度

- **当** 批量导入进行中
- **那么** 显示当前进度（已处理/总数）、当前文件名、文件大小和语句数量

#### 场景：生成报告

- **当** 批量导入完成
- **那么** 输出汇总报告：批次ID、成功数量、失败数量、跳过文件数量、失败文件列表、跳过文件列表

#### 场景：失败文件提示

- **当** 有文件导入失败时
- **那么** 提示用户使用 `--batch-id <ID> --retry-failed` 命令重试失败的文件
