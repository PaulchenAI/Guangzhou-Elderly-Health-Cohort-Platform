# doc-api Specification

## 修改需求

### 需求：文档接口列表查询

系统必须提供 API 接口，支持查询所有文档接口的列表信息，并且只返回允许访问的接口。

#### 场景：获取所有接口列表（带访问控制）

- **当** 调用 `GET /api/core/doc-api/endpoints`
- **那么** 系统必须返回所有**允许访问**的接口列表
- **并且** 系统必须根据配置的访问控制规则过滤接口
- **并且** 只有配置为 `true` 的接口才会被返回
- **并且** 每个接口必须包含以下信息：
  - `operation_id`：接口操作 ID
  - `name`：接口名称
  - `method`：HTTP 方法（GET/POST/PUT/DELETE 等）
  - `path`：接口路径
  - `summary`：接口摘要（如果有）

#### 场景：默认只返回允许访问的接口

- **当** 系统没有配置 `HIS_API_ACCESS_CONTROL` 环境变量
- **那么** 系统必须使用默认配置
- **并且** 默认配置包含 14 个允许访问的接口：
  - ENC_INP_0001 - 住院就诊信息
  - CLI_INP_0001 - 住院患者过敏信息
  - DIAG_INP_0001 - 住院患者诊断信息
  - CLI_INP_0010 - 手术麻醉安排信息
  - CLI_INP_0006 - 住院草药医嘱明细信息
  - CLI_INP_0005 - 患者抗菌药物用药目的信息
  - CLI_NIS_0002 - 体征数据变化信息(支持多院区)
  - CLI_NIS_0001 - 体征数据明细信息
  - CLI_NIS_0021 - 获取压疮记录上报接口
  - MEDINSUR_EMR_0006 - 住院电子病历死亡记录（医保）
  - FIN_INP_0009 - 住院账单明细接口
  - ENC_OUTP_0001 - 门诊患者就诊信息
  - CLI_OUTP_0004 - 患者门诊处方发药信息接口
  - PER_OUTP_0002 - 门诊患者基本健康信息接口
- **并且** 只返回这 14 个接口的列表

#### 场景：支持自定义访问控制配置

- **当** 系统配置了 `HIS_API_ACCESS_CONTROL` 环境变量
- **并且** 配置格式为 JSON 字符串，例如：`{"ENC_INP_0001": true, "CLI_INP_0001": false}`
- **那么** 系统必须使用自定义配置
- **并且** 自定义配置会覆盖默认配置
- **并且** 只有配置为 `true` 的接口才会被返回

#### 场景：配置格式错误时使用默认配置

- **当** `HIS_API_ACCESS_CONTROL` 环境变量格式错误（不是有效的 JSON）
- **那么** 系统必须使用默认配置
- **并且** 系统必须记录警告日志

### 需求：文档接口详情查询

系统必须提供 API 接口，支持查询指定接口的详情信息，并且只允许查询允许访问的接口。

#### 场景：获取允许访问的接口详情

- **当** 调用 `GET /api/core/doc-api/endpoints/{operation_id}`
- **并且** 该接口在访问控制配置中设置为 `true`
- **那么** 系统必须返回接口的完整详情信息
- **并且** 详情必须包含：
  - `operation_id`：接口操作 ID
  - `name`：接口名称
  - `method`：HTTP 方法
  - `path`：接口路径
  - `summary`：接口摘要
  - `description`：接口描述
  - `parameters`：请求参数
  - `request_body`：请求体定义
  - `responses`：响应定义
  - `request_example`：请求示例
  - `response_example`：响应示例

#### 场景：不允许访问的接口返回 403 错误

- **当** 调用 `GET /api/core/doc-api/endpoints/{operation_id}`
- **并且** 该接口在访问控制配置中设置为 `false` 或不存在
- **那么** 系统必须返回 403 Forbidden 错误
- **并且** 错误信息必须包含：`接口 {operation_id} 不允许访问`

### 需求：文档接口搜索

系统必须提供 API 接口，支持搜索文档接口，并且只返回允许访问的接口。

#### 场景：搜索允许访问的接口

- **当** 调用 `POST /api/core/doc-api/endpoints/search`
- **并且** 提供了搜索条件（如 name、path、method、operation_id、keyword）
- **那么** 系统必须在允许访问的接口中进行搜索
- **并且** 只返回匹配搜索条件且允许访问的接口
- **并且** 搜索结果必须遵循访问控制规则

#### 场景：搜索结果不包含不允许访问的接口

- **当** 搜索条件匹配到某个接口
- **并且** 该接口在访问控制配置中设置为 `false` 或不存在
- **那么** 该接口必须被排除在搜索结果之外
- **并且** 即使接口匹配搜索条件，也不会出现在结果中

---

### 需求：接口访问控制配置

系统必须支持通过配置控制哪些接口可以被访问。

#### 场景：从环境变量读取配置

- **当** 系统启动时
- **那么** 系统必须读取 `HIS_API_ACCESS_CONTROL` 环境变量
- **并且** 如果环境变量存在且格式正确，则使用该配置
- **并且** 如果环境变量不存在或格式错误，则使用默认配置

#### 场景：配置格式

- **当** `HIS_API_ACCESS_CONTROL` 环境变量存在
- **那么** 配置必须是有效的 JSON 字符串
- **并且** JSON 格式为：`{"operation_id": true/false, ...}`
- **并且** `operation_id` 为接口的操作 ID（如 "ENC_INP_0001"）
- **并且** 值为布尔类型，`true` 表示允许访问，`false` 表示不允许访问

#### 场景：配置合并策略

- **当** 系统读取配置时
- **那么** 系统必须将环境变量配置与默认配置合并
- **并且** 环境变量配置优先于默认配置
- **并且** 如果某个接口在环境变量配置中不存在，则使用默认配置的值
