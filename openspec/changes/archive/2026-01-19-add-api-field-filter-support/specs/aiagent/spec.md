## 新增需求

### 需求：AI Agent 字段过滤感知

AI Agent 在生成数据查询脚本时，必须感知目标配置的可搜索字段，只使用支持过滤的字段生成查询条件。

#### 场景：获取可搜索字段信息

- **当** AI Agent 检测到用户意图涉及数据过滤查询
- **那么** 系统自动获取目标配置的可搜索字段列表
- **并且** 将字段信息包含在 LLM 提示上下文中

#### 场景：生成带过滤条件的查询脚本

- **当** AI Agent 生成包含过滤条件的查询脚本
- **那么** 过滤条件中的字段必须来自可搜索字段列表
- **并且** 如果用户请求的字段不可搜索，AI 应说明限制并建议可用字段

#### 场景：字段不支持搜索时自动修正

- **当** 脚本执行返回 "字段 xxx 不支持搜索" 错误
- **那么** AI Agent 从错误响应中提取可用字段列表
- **并且** 使用可用字段重新生成查询脚本
- **并且** 向用户说明字段限制和修正内容

### 需求：表查询 API 增强错误提示

表查询 API 在字段不支持搜索时，必须返回可用的搜索字段列表，帮助调用方快速修正。

#### 场景：返回可搜索字段列表

- **当** 查询请求中的过滤字段不支持搜索
- **那么** API 返回 400 错误
- **并且** 错误响应包含 `message` 字段说明错误原因
- **并且** 错误响应包含 `available_fields` 数组列出可搜索字段

#### 场景：查询可搜索字段端点

- **当** 调用 `GET /api/core/table-query/configs/{config_id}/searchable-fields`
- **那么** 返回该配置的所有可搜索字段
- **并且** 每个字段包含 `name`（字段名）、`display_name`（显示名）、`type`（类型）

### 需求：问卷查询 API 字段验证

问卷查询 API 必须验证过滤条件中的字段是否在 Schema 配置的可搜索字段列表中。

#### 场景：验证过滤字段

- **当** 调用 `/survey/query` API 并包含过滤条件
- **那么** 系统验证每个过滤字段是否在 Schema 的可搜索字段列表中
- **并且** 如果字段不可搜索，返回 400 错误和可用字段列表

#### 场景：问卷 Schema 可搜索字段

- **当** 问卷 Schema 配置中的字段标记为 `searchable: true`
- **那么** 该字段可用于 `/survey/query` API 的过滤条件
- **并且** 未标记或标记为 `searchable: false` 的字段不可用于过滤

## 新增需求

### 需求：字段搜索错误自动修正

当脚本因字段不支持搜索而执行失败时，系统必须能够根据错误响应中的可用字段信息自动修正脚本并重试。

#### 场景：字段不支持搜索错误修正

- **当** 脚本执行返回字段不支持搜索的错误
- **那么** 系统从错误响应中提取可用字段列表
- **并且** 分析用户原始意图，选择最匹配的可用字段
- **并且** 使用可用字段重新生成查询条件
- **并且** 重新执行修正后的脚本

#### 场景：无可用字段时的处理

- **当** 配置中没有任何可搜索字段
- **那么** 系统向用户说明该配置不支持字段过滤
- **并且** 建议用户联系管理员配置可搜索字段
- **并且** 提供不带过滤条件的查询作为替代方案
