# SQL 导入功能规范

## 新增需求

### 需求：Oracle SQL 语法转换

系统必须提供将 Oracle SQL 文件转换为 MySQL 兼容语法的能力，只保留表结构和数据。

#### 场景：只保留表结构和数据

- **当** 转换 Oracle SQL 文件
- **那么** 只保留 `CREATE TABLE` 和 `INSERT INTO` 语句，移除其他所有语句（COMMENT、ALTER、DELETE、COMMIT 等）

#### 场景：数据类型转换

- **当** 解析到 Oracle 的 `VARCHAR2(n)` 类型
- **那么** 转换为 MySQL 的 `VARCHAR(n)`

#### 场景：移除 Oracle 存储参数

- **当** 解析到 `tablespace`、`pctfree`、`initrans`、`maxtrans`、`storage` 子句
- **那么** 从输出 SQL 中移除这些子句，并添加 `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4`

#### 场景：移除 PL/SQL 命令

- **当** 解析到 `prompt`、`set feedback`、`set define` 等命令
- **那么** 从输出中移除这些行

#### 场景：转换日期函数

- **当** 解析到 `to_date('date', 'format')` 函数
- **那么** 转换为 `STR_TO_DATE('date', 'mysql_format')`

#### 场景：转换字符串连接符

- **当** 解析到 `'str' || chr(n) || 'str'` 连接表达式
- **那么** 转换为 `CONCAT('str', CHAR(n), 'str')`

---

### 需求：转换后文件保存

系统必须将转换后的 SQL 文件保存到指定目录。

#### 场景：保存到指定目录

- **当** 用户指定输出目录 `docs/hospital/convertsql/`
- **那么** 转换后的文件保存到该目录

#### 场景：文件名前缀

- **当** 用户使用 `--prefix` 参数（例如：`mysql_`）
- **那么** 转换后的文件名添加前缀（例如：`mysql_BS_DEPARTMENT.sql`）

#### 场景：批量转换

- **当** 用户使用 `convert-all` 命令转换目录下所有文件
- **那么** 必须指定输出目录（`-o` 参数），所有转换后的文件保存到该目录

---

### 需求：批量 SQL 文件导入

系统必须支持批量导入转换后的 MySQL SQL 文件到数据库。

#### 场景：读取转换后的文件

- **当** 用户指定转换后的 SQL 文件或目录
- **那么** 系统读取文件内容并执行 SQL 语句

#### 场景：指定目录导入

- **当** 用户指定 `docs/hospital/convertsql/` 目录并使用 `--all` 参数
- **那么** 系统遍历目录下所有 `.sql` 文件并依次导入

#### 场景：导入成功

- **当** SQL 文件执行成功
- **那么** 记录成功日志，继续处理下一个文件

#### 场景：导入失败

- **当** SQL 文件执行失败（语法错误、约束冲突等）
- **那么** 记录错误日志（文件名、错误信息），根据 `--continue-on-error` 参数决定是否继续

#### 场景：预览模式

- **当** 用户使用 `--dry-run` 参数
- **那么** 仅显示 SQL 内容，不执行数据库操作

#### 场景：外键检查处理

- **当** 导入 SQL 文件时
- **那么** 自动禁用外键检查（`SET FOREIGN_KEY_CHECKS = 0`），导入完成后恢复

---

### 需求：导入进度与报告

系统必须提供导入进度显示和最终报告。

#### 场景：显示进度

- **当** 批量导入进行中
- **那么** 显示当前进度（已处理/总数）和当前文件名

#### 场景：生成报告

- **当** 批量导入完成
- **那么** 输出汇总报告：成功数量、失败数量、失败文件列表
