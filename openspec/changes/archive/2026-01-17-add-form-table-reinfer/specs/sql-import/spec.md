## 新增需求

### 需求：基于 Excel 元数据重新推断表含义

系统必须支持从 Excel 文件读取表单元数据，并利用这些上下文信息重新推断表和字段的中文含义。

#### 场景：读取 Excel 元数据

- **当** 用户提供包含表单元数据的 Excel 文件
- **那么** 系统必须解析以下列：
  - `TABLENAME`：表名
  - `FORMDES`：表单分类描述
  - `NAMELABEL`：表单中文名称
- **并且** 表名必须统一转换为大写

#### 场景：查找对应的 JSON 文件

- **当** 处理 Excel 中的某一行数据
- **那么** 系统必须在输出目录中查找 `{TABLENAME}_meaning.json` 文件
- **当** JSON 文件存在
- **那么** 继续处理该表
- **当** JSON 文件不存在
- **那么** 记录该表名并跳过，不报错

#### 场景：获取原始 SQL 文件

- **当** 找到对应的 JSON 文件
- **那么** 系统必须从 JSON 中提取 `file_path` 字段
- **并且** 读取原始 SQL 文件内容
- **当** SQL 文件不存在
- **那么** 尝试在指定的 SQL 目录中查找 `{TABLENAME}.sql`

#### 场景：带上下文的推断

- **当** 重新推断表含义
- **那么** 提示词必须包含以下上下文信息：
  - 表单分类（FORMDES）
  - 表单中文名称（NAMELABEL）
- **并且** LLM 应优先使用 NAMELABEL 作为表的中文含义
- **并且** 字段推断应参考表的业务用途

#### 场景：批量处理

- **当** 用户执行 `reinfer-from-excel` 命令
- **那么** 系统必须遍历 Excel 中的所有行
- **并且** 支持并发处理（通过 `-c/--concurrency` 参数）
- **并且** 支持跳过已存在结果（通过 `--skip-existing` 参数）

#### 场景：处理进度与报告

- **当** 批量处理完成
- **那么** 系统必须输出以下统计信息：
  - 总行数
  - 成功处理数
  - 跳过数（JSON 不存在）
  - 失败数（推断错误）
- **并且** 列出所有跳过的表名

#### 场景：预览模式

- **当** 用户使用 `--dry-run` 参数
- **那么** 系统只显示将要处理的表列表
- **并且** 不执行实际的推断操作
- **并且** 显示哪些表会被跳过（JSON 不存在）
