# 提案：联合查询前端界面

## 概述

基于已实现的联合查询后端 API（`join-query-api`），开发前端用户界面，让用户能够可视化地选择主表和关联表，执行多表联合查询，并展示合并后的数据结果。

## 动机

### 为什么需要这个变更？

1. **后端能力已就绪**：联合查询 API 已完成开发，支持多级关联、LEFT JOIN、字段别名等功能
2. **用户需求**：用户需要在界面上直观地查看多表关联数据，而不是手动编写 SQL
3. **提升效率**：通过可视化界面，用户可以快速配置和执行复杂的多表查询

### 不做这个变更会怎样？

- 后端 API 无法被普通用户使用，只能通过开发人员调用
- 用户需要手动编写 SQL 或使用其他工具查询关联数据
- 浪费已开发的后端能力

## 变更内容

### 1. 新增联合查询页面

在现有表查询功能基础上，添加新的联合查询页面，通过标签页/导航切换：
- 路径：`/table-query/join`
- 与单表查询 `/table-query` 形成并列导航

### 2. 页面布局设计

采用三栏布局：
- **左侧栏**：主表选择器（复用现有表列表组件）
- **中间区域**：关联关系配置面板
  - 展示主表的外键关联关系树
  - 支持勾选/取消要关联的表
  - 支持设置关联深度
- **右侧区域**：数据展示区
  - 联合查询结果表格
  - 支持分页、过滤、排序
  - 提供列显示/隐藏功能

### 3. 关联表选择功能

- 选择主表后，自动调用 `join-preview` API 获取关联关系
- 以树形结构展示关联表（支持展开/折叠）
- 用户可勾选要包含的关联表
- 显示关联字段信息（外键 → 目标字段）

### 4. 数据展示功能

- 合并后的数据以表格形式展示
- 字段使用 `表名_字段名` 格式作为列标题
- 提供列选择器，用户可选择显示/隐藏特定列
- 按表分组的列选择（便于批量操作）

### 5. 查询配置保存功能

- 用户可保存常用的联合查询配置
- 配置包含：主表、关联表列表、关联深度
- 支持快速加载已保存的配置

### 6. 数据导出功能

- 支持导出联合查询结果为 Excel/CSV
- 复用后端 `join-export` API

## 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 大量列导致表格渲染性能问题 | 中 | 使用虚拟滚动、默认隐藏部分列 |
| 关联关系复杂导致用户困惑 | 低 | 提供清晰的关联路径说明和帮助提示 |
| 查询配置存储需要后端支持 | 中 | 新增后端 API 存储配置，或使用 localStorage 临时方案 |
