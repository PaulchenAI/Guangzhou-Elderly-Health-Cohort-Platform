# 设计：文档 API 查询接口

## 上下文

系统已经通过 `api-doc-extractor` 工具将 Word 文档解析为 OpenAPI JSON 格式，存储在 `docs/his/` 目录中：
- `openapi.json`：完整的 OpenAPI 3.x 规范 JSON
- `report.json`：解析报告，包含接口摘要和统计信息

现在需要提供后台 API 接口，让前端或其他系统能够查询这些文档接口信息。

## 目标 / 非目标

### 目标
- 提供统一的 RESTful API 查询文档接口信息
- 支持从本地文件系统读取文档数据
- 支持从外部文档服务 API 查询（可选，如果配置了外部服务）
- 提供接口列表、详情、搜索等功能
- 配置管理统一在 `.env` 文件中

### 非目标
- 不修改 `api-doc-extractor` 工具本身
- 不提供文档编辑功能
- 不提供文档版本管理
- 不实现文档实时同步（使用缓存机制）

## 决策

### 1. 数据源选择策略

**决策**：优先使用本地文件，如果配置了外部 API 则使用外部 API

**理由**：
- 本地文件读取速度快，无需网络请求
- 外部 API 适用于文档服务独立部署的场景
- 通过环境变量控制，灵活切换

**实现方式**：
```python
# 伪代码
if DOC_API_URL:
    # 使用外部 API
    data = doc_api_client.fetch_from_api()
else:
    # 使用本地文件
    data = read_local_file('docs/his/openapi.json')
```

### 2. 数据缓存策略

**决策**：使用内存缓存，缓存时间 5 分钟

**理由**：
- 文档数据不会频繁变化
- 减少文件 I/O 操作，提升性能
- 5 分钟缓存平衡了实时性和性能

**实现方式**：
- 使用 Python 的 `functools.lru_cache` 或简单的字典缓存
- 缓存 key 包含文件修改时间，文件更新后自动失效

### 3. API 设计

**决策**：遵循 RESTful 风格，使用 Django Ninja Router

**理由**：
- 与项目现有 API 风格保持一致
- Django Ninja 提供自动 OpenAPI 文档生成
- 符合项目技术栈

**API 路径设计**：
- `GET /api/core/doc-api/endpoints`：获取所有接口列表
- `GET /api/core/doc-api/endpoints/{operation_id}`：获取指定接口详情
- `POST /api/core/doc-api/endpoints/search`：搜索接口（支持复杂查询）
- `GET /api/core/doc-api/summary`：获取文档摘要信息

### 4. 错误处理

**决策**：区分不同类型的错误，返回合适的 HTTP 状态码

**错误类型**：
- 文件不存在：返回 404
- 文件格式错误：返回 500，包含错误详情
- 接口不存在：返回 404
- 外部 API 连接失败：返回 503（服务不可用）
- 参数错误：返回 400

### 5. 环境变量配置

**决策**：使用可选的环境变量，不强制要求

**配置项**：
- `DOC_API_URL`：文档服务 API 地址（可选）
- `DOC_API_TOKEN`：文档服务 API 认证 Token（可选）

**理由**：
- 如果未配置外部 API，则仅使用本地文件
- 保持配置的灵活性

## 风险 / 权衡

### 风险 1：文件路径硬编码
**风险**：文件路径硬编码可能导致部署环境不兼容

**缓解措施**：
- 使用 `settings.BASE_DIR` 构建相对路径
- 支持通过环境变量配置文档路径（未来扩展）

### 风险 2：外部 API 依赖
**风险**：如果依赖外部 API，服务不可用会影响功能

**缓解措施**：
- 优先使用本地文件，外部 API 为可选
- 实现降级策略：外部 API 失败时自动使用本地文件
- 添加健康检查接口

### 风险 3：大文件性能
**风险**：`openapi.json` 文件可能很大（1.3MB），频繁读取影响性能

**缓解措施**：
- 使用缓存机制
- 只读取需要的部分（如接口列表时只解析 paths）
- 考虑使用数据库存储（未来优化）
