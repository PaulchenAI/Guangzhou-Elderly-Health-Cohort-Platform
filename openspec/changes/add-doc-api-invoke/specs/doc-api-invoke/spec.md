# HIS 接口调用功能规范

## 新增需求

### 需求：HIS 接口代理调用

系统必须提供后端 API，支持代理调用 HIS 真实接口并返回数据。

#### 场景：调用可访问的 HIS 接口

- **当** 调用 `POST /api/core/doc-api/invoke/{operation_id}`
- **并且** `operation_id` 对应的接口在访问控制配置中标记为可访问
- **并且** 请求体包含 `params` 参数对象
- **那么** 系统必须将请求转发到 HIS API
- **并且** 必须返回以下信息：
  - `success`：是否调用成功
  - `status_code`：HIS 返回的 HTTP 状态码
  - `duration_ms`：调用耗时（毫秒）
  - `data`：HIS 返回的原始数据
  - `log_id`：调用日志记录 ID

#### 场景：调用不可访问的接口返回 403

- **当** 调用 `POST /api/core/doc-api/invoke/{operation_id}`
- **并且** `operation_id` 对应的接口未在访问控制配置中授权
- **那么** 系统必须返回 403 错误
- **并且** 错误消息必须说明接口不允许调用

#### 场景：HIS 接口调用超时

- **当** 调用 HIS 接口超过 30 秒未响应
- **那么** 系统必须返回超时错误
- **并且** 必须记录调用日志（标记为失败）

---

### 需求：调用历史持久化存储

系统必须将所有 HIS 接口调用记录保存到 MySQL 数据库。

#### 场景：保存调用成功记录

- **当** HIS 接口调用成功
- **那么** 系统必须保存以下信息到 `doc_api_invoke_log` 表：
  - `operation_id`：接口操作 ID
  - `endpoint_name`：接口名称
  - `method`：HTTP 方法
  - `path`：接口路径
  - `request_params`：请求参数（JSON）
  - `response_data`：响应数据（JSON）
  - `response_status`：HTTP 状态码
  - `duration_ms`：调用耗时
  - `success`：true
  - `user_id`：调用用户 ID
  - `sys_create_datetime`：创建时间

#### 场景：保存调用失败记录

- **当** HIS 接口调用失败（超时、网络错误、服务端错误等）
- **那么** 系统必须保存调用记录
- **并且** `success` 字段必须为 false
- **并且** `error_message` 字段必须包含错误详情

---

### 需求：调用历史查询 API

系统必须提供 API 查询调用历史记录。

#### 场景：分页查询调用历史

- **当** 调用 `GET /api/core/doc-api/invoke-logs`
- **并且** 可选参数包含 `page`、`page_size`、`operation_id`
- **那么** 系统必须返回分页的调用历史列表
- **并且** 按创建时间倒序排列

#### 场景：查询指定接口的调用历史

- **当** 调用 `GET /api/core/doc-api/invoke-logs?operation_id=XXX`
- **那么** 系统必须返回该接口的所有调用记录

---

### 需求：获取默认测试参数

系统必须提供 API 获取接口的默认测试参数。

#### 场景：获取接口默认参数

- **当** 调用 `GET /api/core/doc-api/endpoints/{operation_id}/default-params`
- **那么** 系统必须返回该接口的默认测试参数
- **并且** 优先从接口定义的 `request_example` 获取
- **并且** 如果没有示例，则根据 `request_body` schema 生成空模板

---

### 需求：接口访问状态展示

系统必须在接口列表中展示每个接口的访问状态。

#### 场景：接口列表返回访问状态

- **当** 调用 `GET /api/core/doc-api/endpoints`
- **那么** 每个接口必须包含 `accessible` 字段
- **并且** 值为 `true` 表示可访问，`false` 表示不可访问

#### 场景：前端显示访问状态标签

- **当** 前端展示接口列表
- **那么** 可访问接口必须显示绿色"可访问"标签
- **并且** 不可访问接口必须显示灰色"不可访问"标签

---

### 需求：前端调用测试面板

系统必须在接口详情页面提供调用测试功能。

#### 场景：展示调用测试 Tab

- **当** 用户查看可访问接口的详情
- **那么** 详情抽屉必须显示"调用测试"Tab
- **并且** 不可访问接口不显示此 Tab

#### 场景：编辑请求参数

- **当** 用户在调用测试面板中
- **那么** 必须提供 JSON 编辑器编辑请求参数
- **并且** 必须提供"加载默认参数"按钮

#### 场景：发送调用请求

- **当** 用户点击"发送请求"按钮
- **那么** 系统必须调用后端代理 API
- **并且** 必须显示加载状态
- **并且** 请求完成后必须展示响应结果

#### 场景：表格展示响应数据

- **当** HIS 接口返回数组类型数据
- **那么** 系统必须以表格形式展示数据
- **并且** 支持切换到 JSON 原始格式查看

#### 场景：显示调用结果信息

- **当** 调用完成
- **那么** 必须显示以下信息：
  - HTTP 状态码
  - 调用耗时
  - 成功/失败状态

---

### 需求：调用历史查看

系统必须提供调用历史查看功能。

#### 场景：查看调用历史列表

- **当** 用户访问调用历史页面或组件
- **那么** 必须展示调用历史列表
- **并且** 包含以下列：接口名称、调用时间、状态、耗时

#### 场景：查看历史记录详情

- **当** 用户点击某条历史记录
- **那么** 必须展示该次调用的完整信息
- **并且** 包含请求参数和响应数据
