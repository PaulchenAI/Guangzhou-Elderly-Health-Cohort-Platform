# 问卷数据集成

## 概述

问卷数据集成模块负责对接外部问卷调查系统 API，同步问卷 Schema 定义并导入问卷数据到本地数据库。

外部 API 地址：`http://106.52.105.202:13000`

认证配置存储在 `.env` 文件中：`SURVEY_API_URL`、`SURVEY_API_ADMIN`、`SURVEY_API_PASSWORD`

## 新增需求

### 需求：JWT 认证

系统必须支持通过 JWT 认证访问外部问卷调查 API 的受保护接口。

#### 场景：获取 JWT Token

- **当** 调用需要认证的接口前
- **那么** 系统使用配置的管理员账号密码请求 `/api/auth/token`
- **并且** 获取 `access_token` 用于后续请求

#### 场景：Token 缓存

- **当** JWT Token 未过期
- **那么** 系统复用缓存的 Token
- **并且** 不重复请求认证接口

#### 场景：Token 自动刷新

- **当** JWT Token 即将过期或已过期
- **那么** 系统自动重新获取新的 Token
- **并且** 使用新 Token 继续请求

#### 场景：认证失败处理

- **当** 认证请求失败（账号密码错误、API 不可用）
- **那么** 系统记录错误日志
- **并且** 抛出认证失败异常

---

### 需求：外部 API 客户端

系统必须提供与外部问卷调查 API 通信的客户端。

#### 场景：获取问卷类型列表

- **当** 调用 `get_survey_types()` 方法
- **那么** 系统请求外部 API `/api/survey-types`
- **并且** 返回所有可用问卷类型的列表（类型标识、名称、描述）

#### 场景：获取问卷 Schema

- **当** 调用 `get_survey_schema(survey_type)` 方法
- **那么** 系统请求外部 API `/api/survey-schema/{survey_type}`
- **并且** 返回问卷的完整 Schema 定义（字段、评分规则、解释说明）

#### 场景：搜索问卷数据

- **当** 调用 `search_surveys(params)` 方法
- **那么** 系统携带 JWT Token 请求外部 API `/api/search`
- **并且** 支持按问卷类型、问卷ID、患者姓名、日期范围进行过滤
- **并且** 返回分页的问卷数据列表

#### 场景：API 请求失败处理

- **当** 外部 API 请求失败（网络错误、超时、非 200 响应）
- **那么** 系统记录错误日志
- **并且** 抛出明确的异常信息

---

### 需求：问卷 Schema 同步

系统必须支持将外部问卷 Schema 同步到本地数据库。

#### 场景：首次同步 Schema

- **当** 运行 `python manage.py sync_survey_schemas` 命令
- **那么** 系统获取所有问卷类型列表
- **并且** 为每个类型获取详细 Schema
- **并且** 创建对应的 `SurveySchemaConfig` 记录

#### 场景：增量同步 Schema

- **当** Schema 已存在且运行同步命令
- **那么** 系统比较本地和远程 Schema
- **并且** 更新有变化的 Schema 记录
- **并且** 记录 `last_synced_at` 时间戳

#### 场景：同步指定类型

- **当** 使用 `--type fried` 参数运行同步命令
- **那么** 系统只同步指定类型的 Schema

#### 场景：显示同步进度

- **当** 同步多个 Schema 时
- **那么** 系统显示当前进度（已处理/总数）
- **并且** 显示每个 Schema 的同步状态（新增/更新/跳过）

---

### 需求：问卷数据存储模型

系统必须提供统一的问卷数据存储模型。

#### 场景：存储问卷记录

- **当** 导入问卷数据时
- **那么** 系统创建 `SurveyRecord` 记录
- **并且** 包含：问卷类型、外部问卷ID、患者信息、问卷数据、评分结果、记录时间

#### 场景：问卷ID唯一性

- **当** 导入的问卷 `survey_id` 已存在
- **那么** 系统跳过该记录（不重复导入）
- **并且** 记录跳过原因

#### 场景：支持多种问卷类型

- **当** 存储不同类型的问卷（Fried、Rockwood、GPM、NRS、PSQI、HAMD 等）
- **那么** 系统使用 JSON 字段存储各类型特有的数据
- **并且** 通过 `survey_type` 字段区分类型

---

### 需求：问卷数据导入

系统必须支持从外部 API 批量导入问卷数据。

#### 场景：全量导入

- **当** 运行 `python manage.py import_survey_data` 命令
- **那么** 系统查询外部 API 获取所有问卷数据
- **并且** 批量插入到本地数据库

#### 场景：按类型导入

- **当** 使用 `--type fried` 参数运行导入命令
- **那么** 系统只导入指定类型的问卷数据

#### 场景：按日期范围导入

- **当** 使用 `--start-date 2024-01-01 --end-date 2024-12-31` 参数
- **那么** 系统只导入指定日期范围内的问卷数据

#### 场景：增量导入

- **当** 使用 `--incremental` 参数运行导入命令
- **那么** 系统只导入本地不存在的问卷记录
- **并且** 基于 `survey_id` 判断是否已存在

#### 场景：显示导入进度

- **当** 导入大量数据时
- **那么** 系统显示当前进度（已处理/总数）
- **并且** 显示成功、失败、跳过的数量

#### 场景：导入失败处理

- **当** 单条记录导入失败
- **那么** 系统记录错误日志
- **并且** 继续处理剩余记录
- **并且** 最终报告失败记录列表

---

### 需求：问卷数据查询 API

系统必须提供本地问卷数据的查询接口。

#### 场景：列表查询

- **当** 请求 `GET /api/core/survey/records`
- **那么** 返回分页的问卷记录列表
- **并且** 支持按问卷类型、患者姓名、日期范围过滤

#### 场景：详情查询

- **当** 请求 `GET /api/core/survey/records/{id}`
- **那么** 返回问卷记录的完整详情
- **并且** 包含问卷数据和评分结果

#### 场景：Schema 查询

- **当** 请求 `GET /api/core/survey/schemas`
- **那么** 返回所有已同步的问卷 Schema 列表

#### 场景：Schema 详情

- **当** 请求 `GET /api/core/survey/schemas/{type}`
- **那么** 返回指定类型的问卷 Schema 定义

---

### 需求：定时任务

系统必须支持通过定时任务自动同步 Schema 和导入问卷数据。

#### 场景：创建 Schema 同步定时任务

- **当** 配置 `sync_survey_schemas_task` 定时任务
- **那么** 系统按照 Cron 表达式定期执行 Schema 同步
- **并且** 建议调度频率：每天凌晨执行一次

#### 场景：创建数据导入定时任务

- **当** 配置 `import_survey_data_task` 定时任务
- **那么** 系统按照 Cron 表达式定期执行增量数据导入
- **并且** 建议调度频率：每小时执行一次

#### 场景：任务执行记录

- **当** 定时任务执行时
- **那么** 系统在 `SchedulerLog` 中记录执行状态和结果
- **并且** 在 `SurveyImportLog` 中记录导入详情

#### 场景：任务执行失败

- **当** 定时任务执行失败
- **那么** 系统记录失败原因到日志
- **并且** 不影响下次调度执行

---

### 需求：前端问卷数据查询页面

系统必须提供统一的前端页面管理所有类型的问卷数据。

#### 场景：页面布局

- **当** 用户访问问卷数据查询页面
- **那么** 左侧显示问卷类型选择器（从 `SurveySchemaConfig` 获取）
- **并且** 右侧显示数据展示区

#### 场景：问卷类型选择

- **当** 用户在左侧选择某个问卷类型
- **那么** 右侧表格根据该类型的 Schema 动态生成列
- **并且** 搜索表单根据可搜索字段动态生成
- **并且** 自动加载该类型的问卷数据

#### 场景：搜索过滤

- **当** 用户在搜索表单中输入条件并点击查询
- **那么** 系统根据条件过滤问卷数据
- **并且** 支持按患者姓名、记录时间等字段搜索

#### 场景：分页展示

- **当** 问卷数据超过一页
- **那么** 系统分页展示数据
- **并且** 支持调整每页显示数量

#### 场景：数据导出

- **当** 用户点击导出按钮
- **那么** 系统支持导出为 Excel 或 CSV 格式
- **并且** 导出当前过滤条件下的数据

---

### 需求：菜单初始化

系统必须支持通过管理命令初始化问卷管理菜单。

#### 场景：执行菜单初始化

- **当** 运行 `python manage.py init_survey_menus`
- **那么** 系统创建"问卷管理"父菜单
- **并且** 创建"问卷数据查询"子菜单

#### 场景：强制重建菜单

- **当** 使用 `--force` 参数运行初始化命令
- **那么** 系统删除现有问卷相关菜单后重建

#### 场景：菜单已存在

- **当** 菜单已存在且未使用 `--force` 参数
- **那么** 系统跳过创建
- **并且** 显示菜单已存在的提示
