## 需求
### 需求：联合查询 API

系统必须提供 RESTful API 执行基于外键关系的多表联合查询。

#### 场景：执行联合查询

- **当** 调用 `POST /api/core/table-query/join-query` 接口
- **那么** 系统根据主表的外键关系自动构建 LEFT JOIN 查询
- **并且** 返回合并后的分页数据结果
- **并且** 响应包含关联信息（关联了哪些表、关联深度）

#### 场景：指定主表（按表名）

- **当** 请求体中 `primary_table` 为数据库表名
- **那么** 系统从 `table_foreignkey_metadata` 查找该表的外键关系
- **并且** 支持精确匹配和模糊匹配（后缀匹配、包含匹配）

#### 场景：指定主表（按配置名）

- **当** 请求体中 `primary_table` 为表查询配置的显示名称
- **那么** 系统先解析配置获取实际表名
- **并且** 再查找该表的外键关系

#### 场景：多级关联查询

- **当** 主表 A 通过外键引用表 B，表 B 又通过外键引用表 C
- **那么** 系统按照关联深度依次 LEFT JOIN 各表
- **并且** 最大关联深度由 `max_depth` 参数控制（默认 2，上限 5）
- **例如** A → B → C 为 2 级关联

#### 场景：关联深度限制

- **当** `max_depth` 参数设置为 N
- **那么** 系统只查询 N 级以内的关联表
- **并且** 超过深度限制的关联自动忽略
- **并且** 如果 `max_depth` 超过上限 5，系统使用 5 作为实际值

#### 场景：循环引用检测

- **当** 关联关系中存在循环（如 A → B → A）
- **那么** 系统检测到循环后停止该路径的递归
- **并且** 不会导致无限循环或错误
- **并且** 在响应的 `join_info` 中标记存在循环

---

### 需求：关联方向控制

系统必须只查询主表的出向关系（主表引用的其他表），不查询入向关系（其他表引用主表）。

#### 场景：只查询出向关系

- **当** 执行联合查询
- **那么** 系统只查找主表作为 `source_table` 的外键关系
- **并且** 不查找主表作为 `target_table` 的外键关系（入向引用）

#### 场景：关联表的出向关系

- **当** 多级关联查询时
- **那么** 每一级关联表也只查找其出向关系
- **例如** 主表 A 引用 B，则查找 B 的出向关系找到 C

---

### 需求：LEFT JOIN 语义

系统必须使用 LEFT JOIN 确保主表数据完整性。

#### 场景：主表数据全部保留

- **当** 主表某行数据在关联表中没有匹配记录
- **那么** 该行仍然出现在结果中
- **并且** 关联表的字段值为 null

#### 场景：关联表有匹配数据

- **当** 主表某行数据在关联表中有匹配记录
- **那么** 关联表的字段值正常返回

---

### 需求：字段名处理

系统必须处理多表联合查询时的字段名冲突问题。

#### 场景：字段名添加表名前缀

- **当** 构建 SELECT 字段列表时
- **那么** 每个字段使用 `{表名}_{字段名}` 格式作为别名
- **例如** `gzlry_BS_STAFF.NAME` → `gzlry_BS_STAFF_NAME`

#### 场景：所有表的字段都展示

- **当** 执行联合查询
- **那么** 结果包含主表和所有关联表的全部字段
- **并且** 每个字段都带有表名前缀避免冲突

#### 场景：响应包含字段元信息

- **当** 联合查询返回结果
- **那么** 响应的 `field_info` 字段包含各字段的元信息
- **并且** 元信息包括原始表名、原始字段名、字段类型

---

### 需求：分页支持

系统必须支持联合查询结果的分页。

#### 场景：默认分页参数

- **当** 请求未指定分页参数
- **那么** 使用默认值：`page=1`，`page_size=20`

#### 场景：分页大小限制

- **当** 请求的 `page_size` 超过最大值 100
- **那么** 系统使用 100 作为实际分页大小

#### 场景：分页结果

- **当** 执行分页查询
- **那么** 响应包含 `items`（数据列表）、`total`（总数）、`page`（当前页）、`page_size`（每页数量）

---

### 需求：过滤支持

系统必须支持对联合查询结果进行过滤。

#### 场景：按字段过滤

- **当** 请求包含 `filters` 参数
- **那么** 系统构建 WHERE 子句进行过滤
- **并且** 过滤字段名必须使用带表名前缀的格式

#### 场景：过滤字段验证

- **当** 过滤条件中的字段不在结果字段列表中
- **那么** 系统返回 400 错误
- **并且** 错误信息说明可用的字段列表

#### 场景：支持的过滤操作符

- **当** 使用过滤条件
- **那么** 支持以下操作符：
  - `eq`（等于）、`ne`（不等于）
  - `gt`（大于）、`gte`（大于等于）
  - `lt`（小于）、`lte`（小于等于）
  - `like`（模糊匹配）
  - `in`（包含）
  - `between`（范围）

---

### 需求：排序支持

系统必须支持对联合查询结果进行排序。

#### 场景：按字段排序

- **当** 请求包含 `order_by` 参数
- **那么** 系统按指定字段排序
- **并且** 排序字段名必须使用带表名前缀的格式

#### 场景：默认排序

- **当** 请求未指定排序字段
- **那么** 使用主表的主键字段降序排序

---

### 需求：关联表过滤

系统必须支持指定要包含或排除的关联表。

#### 场景：指定包含的关联表

- **当** 请求包含 `include_tables` 参数
- **那么** 只 JOIN 指定的关联表
- **并且** 其他关联表被忽略

#### 场景：指定排除的关联表

- **当** 请求包含 `exclude_tables` 参数
- **那么** 排除指定的关联表
- **并且** 其他关联表正常 JOIN

#### 场景：包含和排除同时指定

- **当** 同时指定 `include_tables` 和 `exclude_tables`
- **那么** `include_tables` 优先
- **并且** `exclude_tables` 被忽略

---

### 需求：关联关系预览 API

系统必须提供预览表关联关系的 API，帮助用户了解可用的关联。

#### 场景：获取关联关系预览

- **当** 调用 `GET /api/core/table-query/join-preview/{table_name}` 接口
- **那么** 返回该表的关联关系树
- **并且** 支持 `max_depth` 参数控制预览深度

#### 场景：关联关系预览内容

- **当** 获取关联关系预览
- **那么** 返回以下信息：
  - 主表名称
  - 关联表列表（包含表名、关联字段、关联深度）
  - 总关联表数量
  - 字段列表（所有表的字段，带前缀）

---

### 需求：联合查询导出

系统必须支持将联合查询结果导出为文件。

#### 场景：导出联合查询结果

- **当** 调用 `POST /api/core/table-query/join-export` 接口
- **那么** 系统执行联合查询并导出结果
- **并且** 支持 Excel 和 CSV 格式

#### 场景：导出字段表头

- **当** 导出联合查询结果
- **那么** 表头使用与前端表单一致的格式
- **并且** 如果字段有中文注释（`field_comment`），表头格式为 `中文名/字段名 (表名)`
- **并且** 如果字段没有中文注释，表头格式为 `字段名 (表名)`
- **并且** 表头不再直接使用数据库列名（英文别名）

#### 场景：导出行数限制

- **当** 导出数据
- **那么** 默认最大导出行数为 10000
- **并且** 可通过 `max_rows` 参数调整，上限 100000

### 需求：安全防护

系统必须对联合查询进行安全防护。

#### 场景：表名白名单验证

- **当** 执行联合查询
- **那么** 主表和所有关联表必须在外键元数据中存在
- **并且** 不允许查询未记录在元数据中的表

#### 场景：SQL 注入防护

- **当** 构建 SQL 语句
- **那么** 表名和字段名使用白名单验证
- **并且** 值使用参数化查询
- **并且** 标识符使用反引号转义

#### 场景：关联表数量限制

- **当** 关联表数量超过 10 个
- **那么** 系统返回错误
- **并且** 错误信息建议减少关联深度或使用 `include_tables` 限制

---

### 需求：查询日志

系统必须记录联合查询操作用于审计。

#### 场景：记录联合查询操作

- **当** 执行联合查询
- **那么** 系统在 `table_query_log` 表记录
- **并且** `operation` 字段值为 `join_query`
- **并且** 记录包含主表名、关联表列表、过滤条件、记录数、执行时间

### 需求：手动字段匹配关联

系统必须支持用户手动指定字段匹配规则进行联合查询，即使表之间没有外键关系。

#### 场景：执行手动字段匹配关联

- **当** 调用 `POST /api/core/table-query/join-query` 接口
- **并且** 请求体包含 `manual_joins` 参数
- **那么** 系统根据配置的字段匹配规则构建 LEFT JOIN 查询
- **并且** 返回合并后的分页数据结果
- **并且** 手动关联与外键关联可以同时使用

#### 场景：精确匹配关联

- **当** `manual_joins` 中配置 `match_type` 为 `exact`（或未指定）
- **那么** 系统使用 `=` 操作符进行精确匹配
- **例如** `survey_record.patient_name = BS_OLDER.name`
- **并且** JOIN 条件为：`LEFT JOIN BS_OLDER ON survey_record.patient_name = BS_OLDER.name`

#### 场景：模糊匹配关联

- **当** `manual_joins` 中配置 `match_type` 为 `fuzzy`
- **那么** 系统使用 `LIKE` 操作符进行模糊匹配
- **例如** `survey_record.patient_name LIKE CONCAT('%', BS_OLDER.name, '%')`
- **并且** JOIN 条件为：`LEFT JOIN BS_OLDER ON survey_record.patient_name LIKE CONCAT('%', BS_OLDER.name, '%')`
- **注意**：模糊匹配可能导致性能下降，建议在关联字段上建立索引

#### 场景：问卷调查与 older 表手动关联

- **当** 主表为 `survey_record`，配置手动关联到 `BS_OLDER` 表
- **并且** 源字段为 `patient_name`，目标字段为 `name`，匹配类型为 `exact`
- **那么** 系统构建 `LEFT JOIN BS_OLDER ON survey_record.patient_name = BS_OLDER.name`
- **并且** 返回问卷调查数据和对应的 older 表数据
- **并且** 如果问卷调查数据在 BS_OLDER 表中没有匹配记录，BS_OLDER 的字段值为 null

#### 场景：手动关联与外键关联共存

- **当** 同时存在外键关联和手动关联
- **那么** 系统同时处理两种关联方式
- **并且** 先执行外键关联，再执行手动关联
- **并且** 如果手动关联的目标表已在外键关联中存在，则跳过手动关联（避免重复）
- **并且** 外键关联优先于手动关联

#### 场景：手动关联深度限制

- **当** 配置手动关联
- **那么** 手动关联的深度固定为 1（只关联一级）
- **并且** 不支持手动关联的递归关联
- **并且** 如果用户需要多级关联，可以通过外键关联或多次查询实现

#### 场景：手动关联参数验证

- **当** `manual_joins` 中的表名不存在
- **那么** 系统返回 400 错误
- **并且** 错误信息说明表名不存在

- **当** `manual_joins` 中的字段名不存在
- **那么** 系统返回 400 错误
- **并且** 错误信息说明字段名不存在

- **当** `manual_joins` 中的 `match_type` 不是 `exact` 或 `fuzzy`
- **那么** 系统返回 400 错误
- **并且** 错误信息说明 `match_type` 必须是 `exact` 或 `fuzzy`

#### 场景：手动关联数量限制

- **当** 手动关联的目标表数量超过 5 个
- **那么** 系统返回 400 错误
- **并且** 错误信息建议减少手动关联表数量

- **当** 手动关联的总表数（外键关联 + 手动关联）超过 10 个
- **那么** 系统返回 400 错误
- **并且** 错误信息说明关联表数量超限

#### 场景：手动关联字段名处理

- **当** 执行手动关联查询
- **那么** 所有字段使用表名前缀避免冲突
- **例如** `survey_record_patient_name`、`BS_OLDER_name`
- **并且** 响应中的 `field_info` 包含手动关联字段的元信息
- **并且** 手动关联的字段与外键关联的字段使用相同的命名规则

#### 场景：手动关联的过滤和排序

- **当** 执行手动关联查询
- **并且** 请求包含 `filters` 参数
- **那么** 可以使用手动关联表的字段进行过滤
- **并且** 过滤字段名必须使用带表名前缀的格式（如 `BS_OLDER_name`）

- **当** 执行手动关联查询
- **并且** 请求包含 `order_by` 参数
- **那么** 可以使用手动关联表的字段进行排序
- **并且** 排序字段名必须使用带表名前缀的格式

#### 场景：手动关联的查询日志

- **当** 执行包含手动关联的联合查询
- **那么** 系统在 `table_query_log` 表记录
- **并且** `operation` 字段值为 `join_query`
- **并且** 记录包含手动关联信息（关联表、关联字段、匹配类型）
