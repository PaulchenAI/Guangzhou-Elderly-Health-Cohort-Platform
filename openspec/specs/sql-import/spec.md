## 需求
### 需求：Oracle SQL 语法转换

系统必须提供将 Oracle SQL 文件转换为 MySQL 兼容语法的能力，只保留表结构和数据。

#### 场景：只保留表结构和数据

- **当** 转换 Oracle SQL 文件
- **那么** 只保留 `CREATE TABLE` 和 `INSERT INTO` 语句，移除其他所有语句（COMMENT、ALTER、DELETE、COMMIT 等）

#### 场景：数据类型转换

- **当** 解析到 Oracle 的 `VARCHAR2(n)` 类型
- **那么** 转换为 MySQL 的 `VARCHAR(n)`

#### 场景：移除 Oracle 存储参数

- **当** 解析到 `tablespace`、`pctfree`、`initrans`、`maxtrans`、`storage` 子句
- **那么** 从输出 SQL 中移除这些子句，并添加 `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4`

#### 场景：移除 PL/SQL 命令

- **当** 解析到 `prompt`、`set feedback`、`set define` 等命令
- **那么** 从输出中移除这些行

#### 场景：转换日期函数

- **当** 解析到 `to_date('date', 'format')` 函数
- **那么** 转换为 `STR_TO_DATE('date', 'mysql_format')`

#### 场景：转换字符串连接符

- **当** 解析到 `'str' || chr(n) || 'str'` 连接表达式
- **那么** 转换为 `CONCAT('str', CHAR(n), 'str')`

### 需求：转换后文件保存

系统必须将转换后的 SQL 文件保存到指定目录。

#### 场景：保存到指定目录

- **当** 用户指定输出目录 `docs/hospital/convertsql/`
- **那么** 转换后的文件保存到该目录

#### 场景：文件名前缀

- **当** 用户使用 `--prefix` 参数（例如：`mysql_`）
- **那么** 转换后的文件名添加前缀（例如：`mysql_BS_DEPARTMENT.sql`）

#### 场景：批量转换

- **当** 用户使用 `convert-all` 命令转换目录下所有文件
- **那么** 必须指定输出目录（`-o` 参数），所有转换后的文件保存到该目录

---

### 需求：批量 SQL 文件导入

系统必须支持批量导入转换后的 MySQL SQL 文件到数据库。

#### 场景：读取转换后的文件

- **当** 用户指定转换后的 SQL 文件或目录
- **那么** 系统读取文件内容并执行 SQL 语句

#### 场景：指定目录导入

- **当** 用户指定 `docs/hospital/convertsql/` 目录并使用 `--all` 参数
- **那么** 系统遍历目录下所有 `.sql` 文件并依次导入

#### 场景：导入成功

- **当** SQL 文件执行成功
- **那么** 记录成功日志，继续处理下一个文件

#### 场景：导入失败

- **当** SQL 文件执行失败（语法错误、约束冲突等）
- **那么** 记录错误日志（文件名、错误信息），根据 `--continue-on-error` 参数决定是否继续

#### 场景：预览模式

- **当** 用户使用 `--dry-run` 参数
- **那么** 仅显示 SQL 内容，不执行数据库操作

#### 场景：外键检查处理

- **当** 导入 SQL 文件时
- **那么** 自动禁用外键检查（`SET FOREIGN_KEY_CHECKS = 0`），导入完成后恢复

---

### 需求：导入进度与报告

系统必须提供导入进度显示和最终报告，包括文件大小信息、语句数量和时间统计。

#### 场景：显示进度

- **当** 批量导入进行中
- **那么** 显示当前进度（已处理/总数）、当前文件名、文件大小和语句数量

#### 场景：生成报告

- **当** 批量导入完成
- **那么** 输出汇总报告：批次ID、成功数量、失败数量、跳过文件数量、失败文件列表、跳过文件列表

#### 场景：失败文件提示

- **当** 有文件导入失败时
- **那么** 提示用户使用 `--batch-id <ID> --retry-failed` 命令重试失败的文件

### 需求：完整性检查的 INSERT 数量统计

系统必须准确统计目标文件中的 INSERT 语句数量，包括大文件（>10MB）。

#### 场景：大文件使用流式统计

- **当** 检查大文件（>10MB）的完整性时
- **那么** 必须使用流式逐行统计 INSERT 数量，而非只读取部分内容
- **并且** 统计准确率必须达到 100%

#### 场景：小文件读取全部内容

- **当** 检查小文件（<10MB）的完整性时
- **那么** 可以读取全部内容并使用 `count()` 方法统计

#### 场景：避免内存溢出

- **当** 统计 INSERT 数量时
- **那么** 对于大文件必须使用 O(1) 空间复杂度的流式处理
- **并且** 不能一次性加载整个文件到内存

---

### 需求：|| 连接符转换性能优化

系统必须优化 `||` 连接符转换逻辑，避免正则表达式导致的灾难性回溯。

#### 场景：跳过复杂语句

- **当** INSERT 语句包含超过 20 个单引号时
- **那么** 跳过 `||` 连接符转换，避免性能问题

#### 场景：限制字符串长度

- **当** 转换 `||` 连接符时
- **那么** 只匹配长度 ≤ 100 字符的字符串
- **并且** 避免使用嵌套量词的复杂正则表达式

#### 场景：限制替换次数

- **当** 处理包含多个 `||` 的语句时
- **那么** 最多替换 3 次
- **并且** 每次只替换 1 个匹配，及时检测无变化并退出

#### 场景：性能保证

- **当** 转换任意大小的文件时
- **那么** 单个 INSERT 语句的转换时间必须 < 10 毫秒
- **并且** 不能出现 CPU 100% 但无进展的情况

### 需求：导入状态追踪

系统必须记录每个文件的导入状态，支持断点续导和失败重试。

#### 场景：创建状态追踪表

- **当** 首次运行导入命令时
- **那么** 自动创建 `sql_import_log` 表
- **并且** 表结构包含：文件名、文件路径、文件大小、状态、错误信息、开始时间、结束时间、批次ID、语句数量

#### 场景：记录导入状态

- **当** 开始导入文件时
- **那么** 记录状态为 `processing`
- **当** 导入成功时
- **那么** 更新状态为 `success`，记录语句数量和结束时间
- **当** 导入失败时
- **那么** 更新状态为 `failed`，记录错误信息和结束时间
- **当** 跳过文件时
- **那么** 记录状态为 `skipped`，记录跳过原因

#### 场景：批次管理

- **当** 启动新的导入任务时
- **那么** 生成唯一的批次ID（8位UUID）
- **并且** 所有文件的状态记录都关联到该批次ID

#### 场景：查看导入状态

- **当** 用户使用 `--show-status` 参数
- **那么** 显示最近10个批次的统计信息
- **当** 用户使用 `--show-status --batch-id <ID>` 参数
- **那么** 显示指定批次的详细文件列表和状态

#### 场景：断点续导

- **当** 用户使用 `--resume` 参数
- **那么** 自动跳过状态为 `success` 的文件
- **并且** 只导入 `pending` 和 `failed` 状态的文件

#### 场景：重试失败文件

- **当** 用户使用 `--retry-failed` 参数
- **那么** 只重新导入上次失败的文件（状态为 `failed`）
- **并且** 跳过所有成功和待处理的文件

#### 场景：强制重新导入

- **当** 用户使用 `--force` 参数
- **那么** 忽略状态表记录
- **并且** 重新导入所有文件（适用于数据更新场景）

#### 场景：防止重复导入

- **当** 同一批次中文件已成功导入
- **那么** 自动跳过该文件
- **并且** 避免数据重复插入
- **当** 不同批次中导入相同文件
- **那么** 依赖数据库的唯一键约束防止重复数据
- **并且** 忽略 `Duplicate entry` 错误
