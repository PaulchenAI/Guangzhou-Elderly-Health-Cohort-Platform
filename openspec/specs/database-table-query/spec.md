# 数据库表查询管理

## 概述

数据库表查询管理系统允许用户通过配置化的方式查询和展示导入的医院数据，无需为每个表单独编写代码。

### 需求：表查询配置管理

系统必须提供 JSON 配置方式定义表的查询规则，包括可见字段、可搜索字段、排序字段等。

#### 场景：创建表查询配置

- **当** 管理员创建新的表查询配置
- **那么** 系统保存配置到 `table_query_config` 表
- **并且** 配置包含表名、显示名称、字段定义、分页设置等

#### 场景：批量创建配置

- **当** 使用 `batch_create_table_configs` 命令
- **那么** 系统自动检测表结构并批量生成配置
- **并且** 支持按表名前缀过滤

### 需求：动态查询 API

系统必须提供统一的查询 API，支持根据配置动态查询数据库表。

#### 场景：执行分页查询

- **当** 用户请求 `POST /api/core/table-query/query`
- **那么** 系统验证配置和参数
- **并且** 返回分页数据结果

#### 场景：SQL 注入防护

- **当** 查询参数包含恶意 SQL 代码
- **那么** 系统使用参数化查询和白名单验证
- **并且** 拒绝非法操作符和字段名

#### 场景：MySQL 保留关键字处理

- **当** 表或字段名是 MySQL 保留关键字（如 `partition`、`explain`）
- **那么** 系统自动使用反引号转义标识符
- **并且** SQL 执行正常

### 需求：数据导出

系统必须支持将查询结果导出为 Excel 或 CSV 格式。

#### 场景：导出 Excel

- **当** 用户请求导出为 Excel 格式
- **那么** 系统生成 `.xlsx` 文件
- **并且** 包含表头和数据

#### 场景：导出 CSV

- **当** 用户请求导出为 CSV 格式
- **那么** 系统生成 `.csv` 文件
- **并且** 使用 UTF-8-BOM 编码

### 需求：查询日志

系统必须记录所有查询和导出操作用于安全审计。

#### 场景：记录查询操作

- **当** 用户执行表查询
- **那么** 系统在 `table_query_log` 表记录
- **并且** 包含用户ID、表名、操作类型、过滤条件、记录数、执行时间

### 需求：前端查询页面

系统必须提供前端页面支持表切换和数据展示。

#### 场景：表选择器

- **当** 用户访问表查询页面
- **那么** 左侧显示可查询表的列表
- **并且** 支持按配置中的显示名称展示

#### 场景：动态表格

- **当** 用户选择某个表配置
- **那么** 表格列根据配置动态生成
- **并且** 支持分页、排序功能

#### 场景：动态搜索表单

- **当** 表配置包含可搜索字段
- **那么** 搜索表单动态生成对应的输入控件
- **并且** 根据字段类型选择合适的组件

### 需求：菜单初始化

系统必须支持通过管理命令初始化菜单。

#### 场景：执行菜单初始化

- **当** 运行 `python manage.py init_table_query_menus`
- **那么** 系统创建"数据查询"父菜单
- **并且** 创建"表数据查询"子菜单
