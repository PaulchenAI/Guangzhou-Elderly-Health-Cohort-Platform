# oracle-db-export Specification

## Purpose

Oracle 数据库导出工具提供直接连接 Oracle 数据库并导出表结构（DDL）与数据（DML）为 SQL 文件的能力。支持全量导出与增量导出（基于用户指定的增量列），输出结果可继续交给现有转换/修复/导入工具处理。
## 需求
### 需求：Oracle 数据库连接与对象选择

系统必须提供一个位于 `tools/` 的 Oracle 数据库导出工具类，支持连接 Oracle 并选择需要导出的表集合。

#### 场景：使用官方驱动连接 Oracle

- **当** 工具需要连接 Oracle 数据库
- **那么** 工具必须使用 Oracle 官方 Python 驱动 `python-oracledb` 进行连接
- **并且** 默认应支持无需 Instant Client 的 thin 模式连接

#### 场景：从 `.env` 读取数据库配置

- **当** 用户未在命令行显式传入连接参数
- **那么** 工具必须从项目根目录的 `.env` 文件读取 Oracle 连接配置
- **并且** 至少支持以下环境变量（大小写敏感，以 `.env` 实际键名为准）：
  - `ORACLE_DSN`（可选，优先级最高）
  - `ORACLE_HOST`
  - `ORACLE_PORT`
  - `ORACLE_SERVICE_NAME`（或 `ORACLE_SID`，二选一）
  - `ORACLE_USER`
  - `ORACLE_PASSWORD`
- **并且** 当必需配置缺失时，工具必须给出清晰的缺失项提示并退出

#### 场景：指定连接信息并成功连接

- **当** 用户提供 Oracle 连接信息（例如 host/port/service_name 或 DSN）以及用户凭据
- **那么** 工具能够建立数据库连接
- **并且** 在连接失败时输出可定位原因的错误信息（网络/认证/服务名错误）

#### 场景：按 schema 与表过滤导出范围

- **当** 用户指定目标 schema
- **并且** 用户指定 include 表列表或 exclude 表列表（至少一种）
- **那么** 工具只导出匹配范围内的表
- **并且** 在表不存在时给出明确提示

---

### 需求：导出表结构（DDL）为 SQL

系统必须支持将选定表的表结构导出为 SQL 文件。

#### 场景：导出 CREATE TABLE

- **当** 用户执行导出并启用 DDL 导出
- **那么** 工具为每张表生成包含 `CREATE TABLE` 的 SQL 文件
- **并且** 输出应可读、可审计（按表分文件）

#### 场景：导出注释（可选）

- **当** 用户启用“导出注释”选项
- **那么** 工具在 DDL 输出中包含表/列注释（例如 `COMMENT ON TABLE`、`COMMENT ON COLUMN` 或等价形式）

---

### 需求：导出表数据（DML）为 SQL

系统必须支持将选定表的数据导出为可执行的 `INSERT INTO` 语句。

#### 场景：导出 INSERT 语句

- **当** 用户执行导出并启用数据导出
- **那么** 工具为每张表生成包含 `INSERT INTO` 的 SQL 文件
- **并且** 导出应正确处理 `NULL`、字符串转义与日期/时间类型序列化

#### 场景：大表分批导出

- **当** 导出的表数据量较大
- **那么** 工具必须支持分批读取与写入（避免一次性加载到内存）
- **并且** 输出文件写入过程不应导致内存持续增长

---

### 需求：全量导出模式

系统必须提供全量导出模式，导出指定范围内的所有表结构与全量数据。

#### 场景：全量导出并生成清单

- **当** 用户以全量模式运行导出任务
- **那么** 工具导出每张表的 DDL 与全量 DML（按配置启用/禁用）
- **并且** 生成 `manifest.json`，记录：
  - 导出时间
  - schema 与表列表
  - 每张表导出的行数（若可获得）
  - 输出文件路径（DDL/DML）

---

### 需求：增量导出模式（基于增量列）

系统必须提供增量导出模式，基于用户指定的“增量列”按水位线导出新增/变更数据。

#### 场景：使用 JSON 配置文件指定增量列

- **当** 用户提供增量配置文件（JSON）
- **那么** 工具必须从该 JSON 中读取每张表的 `incremental_column`
- **并且** 支持为不同表配置不同的增量列
- **并且** 支持一个可选的默认增量列（未单独配置的表使用默认值）

增量配置文件示例：

```json
{
  "default_incremental_column": "UPDATE_TIME",
  "tables": {
    "BS_DEPARTMENT": { "incremental_column": "LAST_MODIFIED_AT" },
    "BS_AREA": { "incremental_column": "UPDATE_TIME" }
  }
}
```

#### 场景：未指定增量列时默认全量导出

- **当** 用户未显式指定 `incremental_column`
- **并且** 未提供增量配置文件（JSON）
- **那么** 工具必须默认使用全量导出模式
- **并且** 不创建或更新 `checkpoint.json`（除非用户显式启用增量模式）

#### 场景：首次增量导出创建 checkpoint

- **当** 用户以增量模式运行并指定 `incremental_column`
- **并且** checkpoint 文件不存在
- **那么** 工具以“无水位线”的规则运行一次（等同于全量数据导出或按用户指定起始值导出）
- **并且** 导出完成后创建 checkpoint 文件（JSON），记录每张表的水位线值

#### 场景：再次增量导出仅导出新数据

- **当** 用户以增量模式运行
- **并且** checkpoint 中存在某表的上次水位线 `last_value`
- **那么** 工具只导出满足 `incremental_column > last_value` 的记录
- **并且** 导出完成后将该表水位线更新为本次导出数据中的最大值

#### 场景：缺少增量列时的处理

- **当** 用户启用增量模式但某表不具备指定的 `incremental_column`
- **那么** 工具必须失败并明确提示该表不支持增量导出
- **或** 在用户显式启用“跳过不支持表”选项时跳过该表，并在 `manifest.json` 中记录跳过原因

---

### 需求：输出目录结构与可重复运行

系统必须定义一致的输出目录结构，并支持可重复运行的输出策略。

#### 场景：输出目录结构

- **当** 用户指定输出目录
- **那么** 工具在输出目录下生成：
  - `create/`：每表一个 DDL 文件
  - `insert/`：每表一个 DML 文件
  - `manifest.json`：导出清单
  - `checkpoint.json`：增量模式下的水位线（若启用）

#### 场景：覆盖或跳过已存在输出

- **当** 输出文件已存在
- **那么** 工具根据用户选择的策略：
  - 覆盖（重新生成）
  - 或跳过（保持现有文件不变）
